# 35.2 A GPT from scratch

*About 12 hours. Prerequisites: 35.1 (BPE), 29.2 (the transformer block), 26.1 and 26.2 (AdamW, schedules), 25.2 (training loops, checkpoints), 26.5 (sanity checks). Lab: [`lab_35_2_gpt.py`](labs/lab_35_2_gpt.py).*

This is the lesson where the pieces become a language model. Nothing in it is new: the tokenizer is 35.1's, the block is 29.2's, the
optimizer and schedule are 26's, the checkpointing is 25.2's. What's new is putting them together correctly, which is where most people's
first LLM training run goes wrong, silently. The model in the lab has a million parameters and trains for two and a half minutes on a CPU; the
code is structurally the same as what trains GPT-2 (Karpathy's nanoGPT is the canonical small version), and a surprising fraction of what
trains much bigger models.

## The data path

1. **Tokenize once**, offline, the whole corpus, and store the token IDs as a flat array of integers on disk: `uint16` when the vocabulary is under 65,536, `uint32` above. The lab's 850 KB of lessons become 349,000 tokens in a 0.7 MB file.
2. **Memory-map** it (`np.memmap`) and sample training windows by random offset: the file can be terabytes and the loader reads only the windows it needs. Large runs shard the token files and read them sequentially per worker, with a deterministic shuffle so a restart resumes at the same position.
3. **Document boundaries**: concatenate documents with an end-of-text token between them. Windows then span documents, which the model learns to handle; some setups mask attention across document boundaries ("document masking"), which matters more for long contexts.
4. **Hold out validation data by document** (the lab uses whole lesson files), never by random windows of the same text.

Each training example is a window of $n + 1$ tokens: the input is the first $n$ and the target is the last $n$, shifted by one. One forward pass trains all $n$ predictions at once, thanks to the causal mask (29.1).

## The model and its budget

The lab's model is 29.2's pre-norm GPT: token and learned position embeddings, 4 blocks of width 128 with 4 heads, a final LayerNorm, and tied input and output embeddings. 970,000 parameters, 793,000 of them outside the embeddings. Before training, write down the numbers from 33.1:

- **FLOPs per token**: about $6N$ = 5.8 MFLOPs.
- **Tokens it would want**: Chinchilla's rule of thumb (35.4), about 20 tokens per parameter, is 19 million. The lab has 0.35 million. It will see each token about 12 times and overfit. That's deliberate: a small-data regime where overfitting is visible in minutes. Real pretraining runs almost never repeat data more than a few times.

**Initialization** follows GPT-2: normal with standard deviation 0.02, residual output projections scaled by $1/\sqrt{2L}$ (29.2), biases at zero.

## Check before you train

The first number to look at is the loss at step zero. A model that hasn't learned anything should assign roughly uniform probability to the $V$ tokens, so the cross-entropy should be about $\ln V$. The lab gets 7.147 against $\ln 1256 = 7.136$. If the initial loss is much higher, the initialization is too large or the logits are scaled wrong (the model is confidently wrong at random); if it's much lower, something leaks the target into the input, such as a broken causal mask (29.1) or a shift of the targets in the wrong direction. It's 26.5's recipe, and it catches a remarkable number of bugs in thirty seconds.

Other checks worth their time: overfit a single batch to near-zero loss (the model and loss are wired correctly); decode a training batch back to text (the data is what you think); and confirm that changing a future token doesn't change earlier logits (29.1's causality test).

## The training loop

The lab's loop, which is the standard one:

- **AdamW** with $\beta = (0.9, 0.95)$ and weight decay 0.1 **on matrices and embeddings only**, not on biases and LayerNorm gains (two parameter groups).
- **Learning rate**: linear warmup (50 steps) to a peak (3e-3 for this small model; large models use 1e-4 to 6e-4), then cosine decay to 10% of the peak.
- **Gradient clipping** at norm 1.0; log the pre-clipping norm, since spikes are the early warning of instability.
- **Gradient accumulation**: the lab's batch of 32 sequences is two micro-batches of 16, each loss divided by 2 before `backward()`, with one optimizer step after both. The effective batch size of a real run is measured in tokens (GPT-3: 0.5 to 3.2 million tokens per step), reached with accumulation and data parallelism (33.2).
- **Evaluation** every few hundred steps on a fixed set of validation batches (the same ones each time, so the curve isn't noise).
- On GPUs: bf16 autocast (25.3), `torch.compile` and FlashAttention through `F.scaled_dot_product_attention` (33.3).

## Checkpoints

Save everything a restart needs: model weights, the optimizer state (Adam's moments; resuming without them is a different optimization, 25.2), the step (to resume the schedule), and the data loader's RNG or position. Load with `torch.load(..., weights_only=True)`, because a pickled checkpoint can execute code (53.2). The lab trains 20 steps straight, and separately 10 steps, saves, loads into fresh objects and trains 10 more: the parameters are **bit-identical**. If they aren't in your setup, something in the state is missing, and you'll find out the day a node fails at step 300,000.

## Results

| step | train loss | validation loss | validation bits per byte |
|---|---|---|---|
| 250 | 4.09 | 4.23 | 2.52 |
| 500 | 3.54 | 3.83 | 2.28 |
| 750 | 3.16 | 3.61 | 2.15 |
| 1,000 | 2.97 | 3.52 | 2.10 |

The validation loss is still falling at the end, and the gap to the training loss is growing (0.55 nats): the model is memorizing text it has seen 12 times. **Bits per byte** (validation loss in bits, divided by bytes per token) is the tokenizer-independent number (34.1, 35.1). Lab 28.1's character RNN reached about 2.35 bits per character on a similar held-out split of the same lessons, so the transformer is modestly better at equal wall-clock order of magnitude, which is roughly what you'd expect at this scale; 29.2's 30-second benchmark, where the RNN won, is the reminder that the comparison depends on the budget.

The samples show what 2.1 bits per byte buys: the course's formatting (headings, bold list items, LaTeX), its vocabulary ("variance", "likelihood", "ridge regression"), phrases that sound like my sentences, and no meaning at all ("The gradient is among the variance"). Getting from here to a model that explains gradient descent correctly takes more data (35.3), more parameters and compute (35.4), a better architecture (35.5), and post-training (38). About eleven orders of magnitude more compute, in the case of the models you use.

## Sampling

Generation feeds the model its own output: compute the logits for the last position, turn them into a distribution, sample a token, append, repeat. The lab uses **temperature** 0.8 (divide the logits before the softmax; below 1 sharpens the distribution) and **top-k** 40 (sample only among the 40 most likely tokens). 37.1 covers decoding properly, including why greedy decoding loops and what nucleus sampling does. Recomputing the whole window at every step, as the lab does, is quadratic; real inference caches keys and values (37.2).

## What changes at scale

The loop above is the core of every pretraining run. Around it, at scale, you add: data pipelines of 35.3's complexity; mixed precision and fused kernels (33.3); FSDP, tensor and pipeline parallelism (33.2); loss-spike handling (skip the batch, roll back to a checkpoint, lower the learning rate); careful monitoring of per-layer statistics; and evaluation on downstream tasks during training, not just validation loss (39.1). And one big run at the end of many small ones, because hyperparameters are chosen at small scale and extrapolated (35.4).

## Things that will bite you

- **Initial loss far from $\ln V$**: a bug, found in thirty seconds or three days.
- **Targets not shifted, or shifted the wrong way**: a model that "learns" to copy its input.
- **Weight decay on LayerNorm gains and biases**.
- **Gradient accumulation without dividing the loss** (an effective learning rate multiplied by the number of micro-batches), or with BatchNorm (don't).
- **Validation data overlapping training data**, from splitting windows instead of documents.
- **Checkpoints without the optimizer state or data position**.
- **Evaluating on a different random batch each time** and reading noise as progress.
- **`uint16` token files with a vocabulary above 65,535**: silent wraparound.

## Exercises

1. A model has a vocabulary of 50,257 tokens. What should its initial loss be? It starts at 10.9. What's likely wrong?
2. Why is the batch in LLM pretraining measured in tokens rather than sequences?
3. You accumulate gradients over 8 micro-batches but forget to divide each loss by 8. What happens, and why might it seem to work?
4. Validation loss is 3.5 nats per token with a tokenizer averaging 2.4 bytes per token. What's the bits per byte?
5. Your resumed run's loss jumps up for a few hundred steps after every restart. Name three likely causes.
6. How many training tokens would a Chinchilla-optimal run of the lab's model need, and how long would it take at the lab's CPU speed (about 27,000 tokens per second)?

<summary>Answers</summary>

1. $\ln 50257 \approx 10.8$. 10.9 is fine: slightly above uniform, as expected from small random logits. (A start of 30 would mean overly large initial logits, for example an unscaled output layer; a start of 2 would mean leakage.)

2. The computation, the gradient noise, and the learning dynamics depend on how many token predictions contribute to each step, and sequences can have different lengths across setups (context length changes during training, packing). A batch of 1 million tokens is comparable across configurations; "512 sequences" isn't.

3. Gradients are summed instead of averaged, so they're 8 times larger: effectively the learning rate is multiplied by 8 (for SGD) or, for Adam, the effect is partly normalized away by the second-moment estimate, except for epsilon, gradient clipping (which now clips much more often) and weight decay's relative strength. With Adam it can "seem to work" because Adam is roughly invariant to gradient scale, until clipping behavior or the balance with weight decay shows up as a worse model.

4. $3.5 / \ln 2 = 5.05$ bits per token; divided by 2.4 bytes per token: 2.10 bits per byte.

5. The optimizer state wasn't restored (Adam's moments restart from zero, making the first steps unstable); the learning rate schedule restarted (back to warmup or to the peak); the data loader restarted from the beginning or reshuffled differently (repeating recent data or changing the distribution); mixed-precision loss scaler state wasn't restored; or the checkpoint was saved before the last optimizer step completed.

6. About 20 × 970,000 ≈ 19.4 million tokens. At 27,000 tokens per second: about 720 seconds, 12 minutes (in the lab's small-batch setup; the 1,000 steps of the lab process 4.1 million tokens in 152 seconds). Getting 19 million *unique* tokens would require about 55 times more text than this course.
