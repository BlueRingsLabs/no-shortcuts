# 46.2 MDPs, Bellman equations and dynamic programming

*About 8 hours. Prerequisites: 46.1, 02.3 (linear systems), 04.1 (expectations). Lab: [`lab_46_2_mdp_dp.py`](labs/lab_46_2_mdp_dp.py).*

A bandit's actions don't change the world. Most interesting problems aren't like that: a move in a game changes the board, a robot's step
changes where it stands, a recommendation changes what the user does next. The formal object for "actions change the state, and the state
determines what's possible next" is the **Markov decision process**. This lesson defines it, derives the two equations everything else in
reinforcement learning approximates, and solves small MDPs exactly when the model of the world is known. Every algorithm in the rest of the
module is a way of doing what this lesson does, without the model, at scale.

## The MDP

An MDP has:

- states $s \in \mathcal{S}$ and actions $a \in \mathcal{A}$;
- transition probabilities $p(s', r \mid s, a)$: the probability of landing in $s'$ with reward $r$ after taking $a$ in $s$;
- a discount factor $\gamma \in [0, 1)$.

The **Markov property** is the assumption that $s$ contains everything relevant about the past: the next state depends on the current
state and action only. When it fails (the agent can't see something that matters), you either put more history into the state or you're in
a partially observable MDP, which is harder.

A **policy** $\pi(a \mid s)$ says what to do in each state. The **return** from time $t$ is the discounted sum of future rewards,
$G_t = R_{t+1} + \gamma R_{t+2} + \gamma^2 R_{t+3} + \dots$, and the goal is a policy that maximizes its expectation. The discount has two
jobs: it keeps infinite sums finite, and it says how much the future matters compared with now.

The lab's MDP is a 4×4 frozen lake: start top-left, goal bottom-right (reward 1), four holes that end the episode. On the slippery version
the agent moves in the intended direction only a third of the time, and otherwise slides to one side.

## Value functions and the Bellman equations

The **state value** of $s$ under $\pi$ is the expected return starting there, $v_\pi(s) = \mathbb{E}_\pi[G_t \mid S_t = s]$. The **action
value** $q_\pi(s, a)$ is the same after first taking $a$. Because $G_t = R_{t+1} + \gamma G_{t+1}$, values satisfy a recursion, the
**Bellman expectation equation**:

$$v_\pi(s) = \sum_a \pi(a \mid s) \sum_{s', r} p(s', r \mid s, a)\,\big[r + \gamma v_\pi(s')\big].$$

For a fixed policy that's a linear system with one equation per state: $v = r_\pi + \gamma P_\pi v$, so $v = (I - \gamma P_\pi)^{-1} r_\pi$
(02.3). The lab evaluates the shortest-path policy (down, down, right, right, down, right) both ways: by solving the system, and by
iterating $v \leftarrow r_\pi + \gamma P_\pi v$ until it stops changing. On the deterministic lake the start state is worth
$\gamma^5 = 0.7738$ (the reward comes six steps later), reached in 7 sweeps. On the slippery lake the same plan is worth 0.0253: it walks
along holes. No episode was played to learn either number.

The **optimal** value functions satisfy the **Bellman optimality equation**, where the policy's average over actions becomes a max:

$$v_*(s) = \max_a \sum_{s', r} p(s', r \mid s, a)\,\big[r + \gamma v_*(s')\big], \qquad q_*(s, a) = \sum_{s', r} p(s', r \mid s, a)\big[r + \gamma \max_{a'} q_*(s', a')\big].$$

It's nonlinear (the max), so there's no direct solve. But once you have $q_*$, acting optimally is trivial: in every state, take
$\arg\max_a q_*(s, a)$. That's why so much of RL is about estimating $q_*$.

## Dynamic programming

With the model known, two classic algorithms find the optimal policy.

**Value iteration** turns the optimality equation into an update and applies it to every state repeatedly:
$v(s) \leftarrow \max_a \sum p\,[r + \gamma v(s')]$. The update is a contraction (each sweep shrinks the distance to $v_*$ by a factor
$\gamma$), so it converges from any start.

**Policy iteration** alternates two steps until the policy stops changing: *evaluate* the current policy exactly (the linear solve), then
*improve* it by acting greedily with respect to its values. Each improvement is guaranteed not to make any state worse (the policy
improvement theorem), and there are finitely many deterministic policies, so it terminates, usually in very few rounds.

| lake | value iteration sweeps | policy iteration rounds | success of the optimal policy |
|---|---|---|---|
| deterministic | 7 | 7 | 1.000 |
| slippery | 241 | 6 | 0.745 |

Both reach the same values. Policy iteration does few expensive rounds; value iteration many cheap sweeps; real implementations mix the
two (a few evaluation sweeps per improvement). The slippery lake's optimal policy is worth studying:

```

H > v G
```

It points *away* from the goal almost everywhere. With sideways slips, moving toward a wall is the only way to be sure you won't slide into
a hole, so the optimal policy crawls along the edges and lets the slips carry it forward. It's the best possible policy and still fails a
quarter of the time: optimal is not the same as good, and no algorithm can beat the environment's randomness. (It's also the known optimal
policy for this map, a good sanity check for the implementation.)

## The discount factor is part of the problem

The lab solves the slippery lake for four discount factors:

| $\gamma$ | success | mean episode length |
|---|---|---|
| 0.5 | 0.450 | 26.7 |
| 0.9 | 0.726 | 40.7 |
| 0.99 | 0.735 | 43.9 |
| 0.999 | 0.735 | 43.9 |

With $\gamma = 0.5$, a reward 10 steps away is worth $0.5^{10} \approx 0.001$ of one now, so the agent prefers risky shortcuts. That's not
a tuning knob to set for best performance. It encodes what you want: whether a later reward really is worth less (money has interest,
patients prefer earlier cures) or whether you only care about eventually succeeding.

## What dynamic programming needs, and why the rest of RL exists

DP needs the full model $p(s', r \mid s, a)$ and a sweep over every state. Both fail in practice: you rarely know the dynamics (a user, a
market, a robot's contact with the floor), and interesting state spaces are astronomically large or continuous. The rest of this module
removes these requirements one at a time: learning from sampled experience instead of the model (46.3), approximating values with neural
networks instead of tables (46.4), and optimizing policies directly (46.5). The Bellman equations stay underneath all of it: TD learning is
a sampled Bellman backup, and DQN is a Bellman backup with regression.

## Things that will bite you

- **Non-Markov states**: leaving out a variable the dynamics depend on (velocity, time since the last event).
- **A discount factor chosen for convergence speed** rather than for what the problem values.
- **Reward design**: the agent optimizes the reward you wrote, not the one you meant (38.3 had the same lesson).
- **"Optimal" read as "good"**: an optimal policy can still fail often when the environment is noisy.
