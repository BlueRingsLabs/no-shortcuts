In 1948 Claude Shannon, working at Bell Labs on how to send messages over noisy telephone lines, wrote a paper that
created a whole field in one go. He wasn't thinking about machine learning, which didn't exist. And yet: the loss function
you'll use to train almost every classifier and every language model in this course is his, the metric used to compare
language models (perplexity) is his, and the objective behind VAEs, diffusion models, knowledge distillation and RLHF's KL
penalty all come from the same three quantities. This is a short module with a very high return on investment.

## Information as surprise

How much information do you get when you learn that an event with probability $p$ happened? Shannon's answer:

$$I(x) = -\log_2 p(x) \quad \text{bits}$$

Why the logarithm? Three properties you'd want from any measure of "surprise": certain events carry no information ($I = 0$ when $p = 1$), rarer
events carry more, and the information of two independent events adds up ($p(x)p(y) \to I(x) + I(y)$). The log is the only function (up to the
base) that turns products into sums, so it's forced on us.

With base 2 the unit is **bits**; with natural log, **nats**. ML code uses natural logs (so nats), and you convert with $1 \text{ nat} = 1/\ln 2 \approx 1.44$ bits.
A fair coin flip gives $-\log_2(1/2) = 1$ bit. Rolling a 6 on a die gives $\log_2 6 \approx 2.58$ bits. A message saying "the sun rose today" gives about zero.

## Entropy

**Entropy** is the average surprise, the expected information of a draw from $p$:

$$H(p) = -\sum_x p(x)\log p(x) = \mathbb{E}_{x \sim p}[-\log p(x)]$$

(with $0 \log 0 = 0$). It measures uncertainty:

- A deterministic distribution has $H = 0$.
- For $K$ outcomes, the uniform distribution has the maximum, $H = \log K$. (You proved, in 03.4, that the max-entropy distribution with no other
  constraints is uniform, and with a mean constraint it's a softmax.)
- A Bernoulli($p$) has $H = -p\log p - (1-p)\log(1-p)$, which peaks at 1 bit for $p = 0.5$.

### The coding interpretation

Shannon's **source coding theorem** gives entropy a concrete meaning: $H(p)$ bits is the minimum average number of bits per symbol needed to encode
symbols drawn from $p$, losslessly. You achieve it (up to rounding) by giving each symbol a code of length about $-\log_2 p(x)$: frequent symbols get
short codes, rare ones long codes. That's what Huffman coding and arithmetic coding do, and it's why a text file of English compresses well (English
has low entropy per character, roughly 1 to 1.5 bits by Shannon's own estimates, versus the 8 bits ASCII spends).

Hold on to this interpretation, because everything below is about **coding costs**.

For continuous variables, **differential entropy** $h(p) = -\int p(x)\log p(x)\,dx$ plays a similar role, with caveats: it can be negative and it
depends on units. The Gaussian has the maximum differential entropy among all distributions with a given variance, $h = \frac{1}{2}\log(2\pi e\sigma^2)$.
Yet another reason the Gaussian is the "assume the least" default.

## Cross-entropy

Now suppose the data comes from $p$, but you built your code using a *model* $q$ (because you don't know $p$). The average code length you pay is the
**cross-entropy**:

$$H(p, q) = -\sum_x p(x)\log q(x) = \mathbb{E}_{x \sim p}[-\log q(x)]$$

Since the optimal code is the one for $p$ itself, $H(p, q) \ge H(p)$, with equality iff $q = p$ (proved below via KL). The better your model, the fewer
bits you waste.

Now look at the cross-entropy loss from 04.4. For a dataset of labels $y_i$, the empirical distribution $\hat{p}$ puts mass $1/n$ on each observed example,
and the average negative log-likelihood of a model $q$ is

$$-\frac{1}{n}\sum_i \log q(y_i \mid x_i) = H(\hat{p}, q)$$

**Minimizing the cross-entropy loss is maximizing likelihood, and it's also minimizing the number of bits your model needs to encode the training
labels.** Three views of the same number. When a language model reports a training loss of 2.3 nats per token, it means: if you used this model to
compress text like the training data (with arithmetic coding), you'd spend about $2.3 \times 1.44 \approx 3.3$ bits per token. That's not a metaphor:
LLMs are genuinely very good compressors, and there's a nice paper by DeepMind (Delétang et al., 2023) showing a language model compressing
images and audio better than PNG and FLAC.

For one-hot labels, the cross-entropy of a single example is just $-\log q(\text{true class})$: the only term that survives is the probability you assigned
to the right answer. Assign it 0.9, pay 0.105 nats. Assign it 0.01, pay 4.6 nats. Assign it 0, pay infinity, which is why you never let a model output
exactly zero probability for anything that could happen (label smoothing, 26.3, and clipping in log loss implementations).

## KL divergence

The **Kullback-Leibler divergence** is the extra cost of using $q$ when the truth is $p$:

$$D_{\text{KL}}(p \,\|\, q) = \sum_x p(x)\log\frac{p(x)}{q(x)} = H(p, q) - H(p)$$

Properties:

- **Non-negative**: $D_{\text{KL}}(p \| q) \ge 0$, with equality iff $p = q$. Proof by Jensen (04.3): $-D_{\text{KL}} = \sum p \log\frac{q}{p} \le \log\sum p\frac{q}{p} = \log\sum q = 0$,
  because log is concave. That's Gibbs' inequality, and it's why cross-entropy is minimized at $q = p$.
- **Not symmetric**: $D_{\text{KL}}(p \| q) \ne D_{\text{KL}}(q \| p)$ in general. It's not a distance (no triangle inequality either), which is why it's called a
  "divergence".
- **Infinite if $q(x) = 0$ where $p(x) > 0$**: using a code with no word for something that happens is infinitely costly.

Since $H(p)$ doesn't depend on the model, minimizing $H(p, q)$ over $q$ is the same as minimizing $D_{\text{KL}}(p \| q)$. **Maximum likelihood is minimizing
the KL divergence from the data distribution to the model.** That's the deepest single sentence in this module.

### The asymmetry matters: forward vs reverse KL

Suppose $p$ is bimodal (two humps) and you fit a single Gaussian $q$:

- **Forward KL**, $D_{\text{KL}}(p \| q)$ (what MLE minimizes): heavily penalizes $q$ being small where $p$ has mass. So $q$ spreads out to **cover both modes**,
  putting mass in the valley between them. "Mean-seeking" or "mass-covering".
- **Reverse KL**, $D_{\text{KL}}(q \| p)$ (what variational inference minimizes, 31.1): heavily penalizes $q$ putting mass where $p$ has little. So $q$ **locks onto
  one mode** and ignores the other. "Mode-seeking".

This explains real behaviour you'll see later: VAEs trained with variational objectives produce blurry averages in some settings and mode-dropping in
others; GANs are prone to mode collapse (31.2); and the KL penalty in RLHF (38.3), $D_{\text{KL}}(\pi_\theta \| \pi_{\text{ref}})$, is a reverse KL that lets the
fine-tuned model concentrate on some behaviours of the reference model while staying inside its support. The lab fits both and shows you the
pictures in numbers.

### Where KL shows up

- **Classification and language modeling**: cross-entropy loss = KL to the data + constant.
- **Knowledge distillation** (49.3): train a small student to match the teacher's full output distribution, minimizing KL between them, often with a
  temperature to soften both.
- **VAEs** (31.1): the ELBO contains $D_{\text{KL}}(q(z \mid x) \,\|\, p(z))$, keeping the encoder's latent distribution close to the prior. For Gaussians it has a
  closed form: $D_{\text{KL}}(\mathcal{N}(\mu, \sigma^2) \,\|\, \mathcal{N}(0, 1)) = \frac{1}{2}(\mu^2 + \sigma^2 - \log\sigma^2 - 1)$.
- **RLHF and policy optimization** (38.3, 46.6): KL penalties keep the policy from drifting too far, too fast.
- **Drift detection** (51.1): the Population Stability Index used in credit risk monitoring is a symmetrized KL between binned distributions.

### Jensen-Shannon, briefly

If you need a symmetric, bounded measure: $\text{JS}(p, q) = \frac{1}{2}D_{\text{KL}}(p \| m) + \frac{1}{2}D_{\text{KL}}(q \| m)$ with $m = \frac{1}{2}(p + q)$. It's between 0 and
$\log 2$, and its square root is a true metric. The original GAN objective, at the optimal discriminator, minimizes it (31.2).

## Perplexity

For language models, the standard metric is **perplexity**: the exponential of the average cross-entropy per token,

$$\text{PPL} = \exp\left(-\frac{1}{N}\sum_{t=1}^N \log q(x_t \mid x_{<t})\right)$$

Interpretation: the model is as uncertain, on average, as if it had to choose uniformly among PPL options at each step. A perplexity of 1 means
certainty; a uniform model over a 50,000-token vocabulary has perplexity 50,000. Two cautions: perplexities are only comparable with the **same
tokenizer** (34.1, 35.1), because the "per token" denominator changes with tokenization, and lower perplexity on web text doesn't guarantee a better
assistant (39.1).

> nan`, forever. My code computed `softmax`, then `log`, then the cross-entropy, in three tidy lines. At fp16, a confident prediction

> `log_softmax` does the same math with the log-sum-exp trick and never produces that zero. Three tidy lines, one sleepless week.

## Things that will bite you

- **Zero probabilities** turning log loss into infinity. Clip predictions (scikit-learn's `log_loss` does) or smooth.
- **Mixing bits and nats**, or log bases between libraries.
- **KL argument order**: `scipy.stats.entropy(p, q)` computes $D_{\text{KL}}(p \| q)$; PyTorch's `F.kl_div(input, target)` expects `input` as *log-probabilities of $q$*
  and `target` as $p$, computing $D_{\text{KL}}(p \| q)$. Read the docs every time. Everyone gets this wrong at least once.
- **Comparing perplexities across tokenizers.**

5. A language model has a cross-entropy of 3.0 nats per token on a test set. What's its perplexity? How many bits per token would it need to compress
