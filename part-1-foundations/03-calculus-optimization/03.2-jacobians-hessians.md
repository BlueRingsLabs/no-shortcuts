# 03.2 Jacobians, Hessians and Taylor: the local picture

*About 10 hours. Prerequisites: 03.1, 02.4. Lab: [`lab_03_2_jacobians_hessians.py`](labs/lab_03_2_jacobians_hessians.py).*

The gradient tells you which way is downhill. It doesn't tell you whether you're in a narrow ravine, on a wide flat
plain, or balanced on a saddle between two mountains. For that you need second derivatives. And when your function
outputs a vector instead of a number (a layer of a neural network, say), the derivative becomes a matrix, the
Jacobian, and backpropagation turns out to be a very disciplined way of multiplying Jacobians without ever writing
one down.

This lesson gives you the local picture of a function: first order (Jacobian), second order (Hessian), and the
Taylor expansion that ties them together. It's the theory behind why optimizers behave the way they do.

## The Jacobian

For a function $f: \mathbb{R}^n \to \mathbb{R}^m$, the **Jacobian** $J_f(x) \in \mathbb{R}^{m \times n}$ collects all the partial
derivatives:

$$J_f(x)_{ij} = \frac{\partial f_i}{\partial x_j}$$

Row $i$ is the gradient of output $i$ (transposed). The local linear approximation is exactly what you'd guess:

$$f(x + h) \approx f(x) + J_f(x)\,h$$

The Jacobian *is* the best linear map approximating $f$ near $x$. If $f$ is already linear, $f(x) = Ax$, the Jacobian is just
$A$ everywhere. Otherwise it changes from point to point.

Examples you need:

- Elementwise functions ($\operatorname{ReLU}$, $\sigma$, $\tanh$ applied to each coordinate) have **diagonal** Jacobians:
  output $i$ depends only on input $i$. For ReLU, the diagonal is 1 where $x_i > 0$ and 0 elsewhere. This is why ReLU
  gradients are a simple mask.
- Softmax $p = \operatorname{softmax}(z)$ has a full Jacobian, because every output depends on every input through the
  normalization:

$$\frac{\partial p_i}{\partial z_j} = p_i(\delta_{ij} - p_j) \qquad \Longleftrightarrow \qquad J = \operatorname{diag}(p) - pp^\top$$

  You'll verify it in the lab. Notice that $J$ is symmetric and that $J\mathbf{1} = 0$: adding the same constant to every
  logit doesn't change the softmax (the "subtract the max" trick from 01.3 relies on exactly this).

## The chain rule is Jacobian multiplication

For a composition $f = f_L \circ \cdots \circ f_2 \circ f_1$ (a neural network, for instance), the chain rule says

$$J_f = J_{f_L} \cdots J_{f_2} J_{f_1}$$

each evaluated at the right intermediate point. That's the whole chain rule in one line: Jacobians multiply, like the
linear maps they are (02.2). The order in which you multiply them is where forward and reverse mode differ, and
associativity (02.2) tells you it doesn't change the answer, only the cost.

Suppose the final output is a scalar loss, so $J_{f_L}$ is a $1 \times m$ row vector. Then:

- **Reverse mode** multiplies from the left: start with the row vector $\partial L / \partial(\text{output})$ and multiply it into
  each Jacobian in turn. Every intermediate result is a *vector* (a row vector times a matrix). These are
  **vector-Jacobian products (VJPs)**.
- **Forward mode** multiplies from the right: start from a direction in input space and push it forward. These are
  **Jacobian-vector products (JVPs)**.

The key practical point: **you never need to build the Jacobian.** For an elementwise ReLU on a vector of size a
million, the Jacobian is a million by million diagonal matrix; the VJP is just `grad_out * (x > 0)`. For a linear layer
$y = Wx$, the VJP with respect to $x$ is $W^\top g$, and with respect to $W$ it's $g x^\top$. Every operation in PyTorch
comes with a hand-written VJP function, and backprop chains them together. You'll write these functions yourself in
24.3.

## The Hessian

For a scalar function $f: \mathbb{R}^n \to \mathbb{R}$, the **Hessian** is the matrix of second partial derivatives:

$$H_{ij} = \frac{\partial^2 f}{\partial x_i\,\partial x_j}$$

It's the Jacobian of the gradient. For any function with continuous second derivatives (everything we care about,
kinks aside), the order of differentiation doesn't matter, so **the Hessian is symmetric**. And symmetric means the
spectral theorem applies (02.4): it has real eigenvalues and orthogonal eigenvectors. That's going to be very useful
in a moment.

Examples:

- $f(w) = \|Xw - y\|^2$: gradient $2X^\top(Xw - y)$, Hessian $2X^\top X$. Constant, because the function is quadratic.
- Logistic regression loss (17.3): Hessian $X^\top D X$ with $D = \operatorname{diag}(p_i(1 - p_i))$. PSD, so the loss is convex.
- A neural network loss: a huge, non-constant, indefinite matrix. With a billion parameters it has $10^{18}$ entries.
  Nobody computes it. But its *eigenvalues* govern how training behaves, and we can estimate the important ones using
  only Hessian-vector products, which are cheap (see below).

## Taylor's theorem: the local picture

Put it together. Near a point $x$:

$$f(x + h) \approx f(x) + \nabla f(x)^\top h + \frac{1}{2}\,h^\top H(x)\,h$$

The first-order term is the slope; the second-order term is the curvature. This quadratic approximation is the single
most useful model of a loss surface. Almost everything we know about optimization is derived by pretending the function
is exactly this quadratic.

Use the eigen-decomposition $H = Q\Lambda Q^\top$ and write $h$ in the eigenvector basis. The curvature term becomes
$\frac{1}{2}\sum_i \lambda_i\,(q_i^\top h)^2$: along eigenvector $q_i$, the function curves with "stiffness" $\lambda_i$.

- Large $\lambda_i$: steep, narrow direction. Small steps needed.
- Small $\lambda_i$: flat direction. You could take big steps.
- Negative $\lambda_i$: the function curves *down*. You're not at a bottom in this direction.

## Critical points and what they look like

At a **critical point** the gradient is zero, so the quadratic term is all that's left. The eigenvalues of the Hessian
classify it:

| Hessian eigenvalues | Critical point | Picture |
|---|---|---|
| all $> 0$ | local minimum | bowl |
| all $< 0$ | local maximum | dome |
| mixed signs | saddle point | horse saddle, Pringles chip |
| some $= 0$ | degenerate: can't tell to second order | flat valley |

In low dimensions, we worry about local minima. In high dimensions, the story changes. Think about it: for a critical
point to be a local minimum, *all* of its (say) million Hessian eigenvalues must be positive. If the signs were
roughly random, the chance of that would be astronomically small. Most critical points in high-dimensional losses are
**saddle points**, and the research on deep network loss surfaces (Dauphin et al., 2014, among others) supports the
picture that the ones with high loss are overwhelmingly saddles, while the local minima tend to have loss close to the
global one. That's one reason why simple gradient descent works much better on neural networks than 1990s intuition
predicted: it's not getting trapped in bad minima nearly as much as feared; it's more often slowed down on plateaus and
near saddles. Noise in stochastic gradients helps escape them (26.1).

## Newton's method

If the quadratic model is good, why not jump straight to its minimum? Setting the gradient of the Taylor approximation
to zero:

$$\nabla f + H h = 0 \quad \Rightarrow \quad h = -H^{-1}\nabla f$$

That's the **Newton step**. On an exact quadratic, it reaches the minimum in one step, whatever the conditioning. Near a
minimum of a smooth function, it converges *quadratically* (the number of correct digits roughly doubles each step).
Logistic regression solvers, GLM fitters and many classical statistical routines use Newton or its variants.

So why don't we train neural networks with Newton's method?

1. **Size**: storing $H$ for $10^9$ parameters needs $10^{18}$ numbers. Solving with it costs $O(n^3)$. Not happening.
2. **Saddles**: on non-convex functions, $H$ has negative eigenvalues, and the Newton step moves *towards* saddle points
   and maxima (it looks for any point with zero gradient). You have to modify it (damping, trust regions).
3. **Noise**: with mini-batches, the Hessian estimate is noisy and inverting a noisy matrix amplifies the noise.

What survives in practice are approximations: **quasi-Newton** methods like L-BFGS that build a low-rank curvature
estimate from recent gradients (great for small-to-medium convex problems; it's the default solver for scikit-learn's
`LogisticRegression`), diagonal approximations of curvature (in spirit, what Adam's per-parameter scaling does, 26.1),
and structured approximations like K-FAC and Shampoo for large networks, which remain an active research area.

### Hessian-vector products

You can compute $Hv$ for any vector $v$ without ever forming $H$, at the cost of about two gradient evaluations. The
trick: $Hv$ is the directional derivative of the gradient in direction $v$,

$$Hv = \lim_{\epsilon \to 0}\frac{\nabla f(x + \epsilon v) - \nabla f(x - \epsilon v)}{2\epsilon}$$

and autodiff frameworks can compute it exactly by differentiating through the gradient computation (forward-over-reverse
mode). With Hessian-vector products you can run power iteration (02.4) to find the largest Hessian eigenvalue, which
tells you the sharpest curvature of your loss, and therefore the largest stable learning rate (03.3). Researchers use
this to study training dynamics, like the "edge of stability" phenomenon where the top eigenvalue hovers right at the
threshold $2/\eta$.

## Things that will bite you

- **Materializing Jacobians** when you only need VJPs. A "just compute the Jacobian" in a custom layer can turn a
  kilobyte computation into gigabytes.
- **Assuming a zero gradient means a minimum.** It might be a saddle or a plateau. Check the loss trend and, for small
  problems, the Hessian eigenvalues.
- **Newton on non-convex problems** without safeguards: it will happily converge to a maximum.
- **Forgetting the $\frac{1}{2}$** in the second-order Taylor term. It's there because $\frac{d^2}{dh^2}\frac{1}{2}\lambda h^2 = \lambda$.
