# 01.3 NumPy and vectorization: thinking in arrays

*About 12 hours. Prerequisites: 01.1. Lab: [`lab_01_3_vectorization.py`](labs/lab_01_3_vectorization.py).*

A Python `for` loop over a million numbers takes about a tenth of a second. The same operation in NumPy takes
about a millisecond. That factor of 100 is the difference between a feature pipeline that runs in a minute and
one that runs over lunch, and it's also the reason every framework in this course (pandas, scikit-learn, PyTorch,
JAX) has the same design at its core: an n-dimensional array of one dtype in contiguous memory, and operations
that run in compiled code over the whole array at once.

Learning NumPy isn't learning a library. It's learning to *think in arrays*: to see a computation as operations
on whole blocks of numbers instead of a loop over individual ones. Once that clicks, PyTorch is NumPy with a
GPU and gradients, and you'll read model code much faster.

## What an ndarray actually is

An `ndarray` is a pointer to a block of memory plus some metadata that says how to interpret it:

- `dtype`: what each element is (`float64`, `float32`, `int64`, `bool`, ...), and so how many bytes it takes.
- `shape`: the size along each dimension.
- `strides`: how many **bytes** to jump in memory to move one step along each dimension.

```python
import numpy as np

a = np.arange(12, dtype=np.float64).reshape(3, 4)
a.shape     # (3, 4)
a.dtype     # float64, 8 bytes per element
a.strides   # (32, 8): +32 bytes to go down a row (4 elements * 8), +8 to go right one column
a.nbytes    # 96
```

Why should you care about strides? Because they explain the two most important performance facts in NumPy:

1. **Many operations don't copy data.** Transposing, slicing with steps, and reshaping (usually) just create a
   new array header with different shape and strides pointing at the *same* memory. That's a **view**.
2. **Memory layout affects speed.** Reading memory sequentially is much faster than jumping around (caches,
   explained in 07.3). Summing along the contiguous axis is faster than along the strided one.

```python
t = a.T
t.strides           # (8, 32): same memory, strides swapped
t.base is a         # True: t is a view of a
np.shares_memory(a, t)  # True
```

### Views vs copies: the rule you must internalize

- **Basic slicing** (`a[1:3]`, `a[:, ::2]`, `a[0]`) returns a **view**. Modifying it modifies the original.
- **Fancy indexing** (with an integer array or a list: `a[[0, 2]]`) and **boolean masking** (`a[a > 5]`) return a
  **copy**.

```python
row = a[0]          # view
row[:] = -1         # a[0] is now all -1
sel = a[[1, 2]]     # copy
sel[:] = 99         # a is unchanged
```

This is a feature: views make slicing free. It's also a trap: a function that modifies a slice of its input can
corrupt the caller's data. When you must be safe, `.copy()` explicitly. PyTorch has the exact same semantics
(`tensor.view`, `tensor.clone()`), and pandas has a more confusing version of it that we'll meet in 10.1.

## Vectorization: moving the loop into C

Here's a function that computes the squared Euclidean distance between every pair of points in two sets. The
loop version:

```python
def pairwise_sq_dists_loop(A, B):
    n, m = len(A), len(B)
    D = np.empty((n, m))
    for i in range(n):
        for j in range(m):
            D[i, j] = np.sum((A[i] - B[j]) ** 2)
    return D
```

For 1,000 x 1,000 points in 64 dimensions that takes seconds. You can vectorize in two steps. First, remove the
inner loop by broadcasting (next section), and then remove all loops using a bit of algebra:

$$\|a - b\|^2 = \|a\|^2 - 2\,a^\top b + \|b\|^2$$

which, for all pairs at once, is

$$D = \operatorname{sq}(A)\,\mathbf{1}_m^\top \;-\; 2\,A B^\top \;+\; \mathbf{1}_n \operatorname{sq}(B)^\top$$

where $\operatorname{sq}(A)$ is the vector of squared row norms. In NumPy:

```python
def pairwise_sq_dists(A, B):
    """A: (n, d), B: (m, d) -> (n, m) squared Euclidean distances."""
    sq_a = np.sum(A * A, axis=1)[:, None]     # (n, 1)
    sq_b = np.sum(B * B, axis=1)[None, :]     # (1, m)
    D = sq_a - 2.0 * (A @ B.T) + sq_b         # (n, m) by broadcasting
    return np.maximum(D, 0.0)                 # rounding can produce tiny negatives; distances can't be negative
```

That's hundreds of times faster, because the heavy part is now a matrix multiplication, which NumPy hands to a
BLAS library that uses SIMD instructions and all your cores. You'll see this exact trick inside k-NN (19.1),
k-means (21.1), kernels (19.3) and attention (29.1, where $QK^\top$ is the same idea).

Notice the `np.maximum(D, 0.0)`. For two nearly identical points, $\|a\|^2 + \|b\|^2 - 2a^\top b$ subtracts two
large nearly equal numbers, and floating point rounding can give `-1e-13`. Take a square root of that and you get
`nan`. The fast formula is numerically worse than the naive one. There's always a price. Module 07.2 is about
paying it knowingly.

## Broadcasting

Broadcasting is how NumPy combines arrays of different shapes without copying. The rules:

1. Line up the shapes from the **right**.
2. Two dimensions are compatible if they are equal, or if one of them is 1.
3. Missing dimensions on the left are treated as 1.
4. Size-1 dimensions are virtually stretched (stride 0, no copy) to match.

```
A:      (n, 1)          x  (column of row norms)
B:         (m,)   ->  (1, m)
result: (n, m)
```

```python
x = np.array([[1.0], [2.0], [3.0]])   # (3, 1)
y = np.array([10.0, 20.0])            # (2,)
x + y
# array([[11., 21.],
#        [12., 22.],
#        [13., 23.]])                  # (3, 2)
```

Typical uses, which you'll write constantly:

```python
X = rng.normal(size=(1000, 5))
X_centered = X - X.mean(axis=0)                    # (1000, 5) - (5,)  -> subtract column means
X_std = X_centered / X.std(axis=0)                 # per-column standardization
row_normalized = X / X.sum(axis=1, keepdims=True)  # (1000, 5) / (1000, 1) -> each row sums to 1
```

`keepdims=True` keeps the reduced axis as size 1 so the result broadcasts back correctly. Without it, `X.sum(axis=1)`
has shape `(1000,)`, which lines up from the right against the 5 columns, and you get an error (or, worse, if the
shapes happen to match, a silently wrong answer).

### The most expensive bug in NumPy

Broadcasting is also how one of the most common ML bugs happens:

```python
y_true = np.array([1.0, 2.0, 3.0])            # shape (3,)
y_pred = model_output.reshape(-1, 1)          # shape (3, 1), as many models return
mse = np.mean((y_true - y_pred) ** 2)         # (3,) - (3,1) -> (3, 3) !!
```

`y_true - y_pred` doesn't fail. It broadcasts into a 3x3 matrix of every true value minus every prediction, and the
mean of that is a number that *looks* like an MSE. The model will even "train" on it. I have seen this bug in
production code, in Kaggle notebooks with thousands of upvotes, and, once, in my own code, which is how I learned
to write the next line:

```python
assert y_true.shape == y_pred.shape, (y_true.shape, y_pred.shape)
```

Check shapes explicitly at function boundaries. It costs nothing and it catches the bugs that cost the most.

## Axis semantics

`axis=k` means "the operation runs *along* axis k, and axis k disappears from the result":

```python
X.shape               # (1000, 5): 1000 samples, 5 features
X.mean(axis=0).shape  # (5,): mean over samples -> one number per feature
X.mean(axis=1).shape  # (1000,): mean over features -> one number per sample
```

Convention in this whole course, and in scikit-learn: **rows are samples, columns are features**. Data matrix
$X \in \mathbb{R}^{n \times d}$. PyTorch keeps the batch dimension first too.

## `einsum`: when the shapes get complicated

For operations on 3+ dimensional arrays, `np.einsum` lets you write the index formula directly:

```python
np.einsum("ij,jk->ik", A, B)          # matrix product A @ B
np.einsum("ij,ij->i", A, B)           # row-wise dot products
np.einsum("bij,bjk->bik", P, Q)       # batched matmul (same as P @ Q for 3-D)
np.einsum("bhqd,bhkd->bhqk", Q, K)    # attention scores: batch, heads, queries, keys (see 29.1)
```

The rule: indices that appear in the inputs but not in the output are summed over. It's the Einstein summation
convention from physics. It reads like the math, which makes it the least error-prone way to write tensor
contractions. The last line is exactly the attention computation in a transformer; you'll write it for real in
module 29.

## Dtypes and memory

- `float64` is NumPy's default. Deep learning uses `float32`, `bfloat16` and `float16`. Mixed precision is in 25.3.
- Integer arrays overflow silently: `np.array([2**62], dtype=np.int64) * 4` wraps around to a negative number with
  no error. Python ints don't overflow; NumPy ints do.
- `np.nan` is a float. An integer array can't hold NaN, which is why pandas converts integer columns with missing
  values to float (and why IDs sometimes become `1.2345e+06` in your CSV exports).
- Memory adds up fast: a `(100_000, 1_000)` float64 array is 800 MB. Know your `nbytes`.

## Randomness done right

Use the `Generator` API, not the legacy global `np.random.seed`:

```python
rng = np.random.default_rng(seed=42)
rng.normal(size=(3, 2))
rng.integers(0, 10, size=5)
rng.permutation(10)
rng.choice(100, size=10, replace=False)
```

Pass `rng` into functions that need randomness instead of relying on global state. Global seeds are shared by every
library you import, so one library drawing an extra random number shifts every draw after it, and your
"reproducible" experiment silently isn't. Explicit generators make randomness a parameter, which is what it is.

## Performance guidelines

- **Avoid Python loops over elements.** Loop over *chunks* if data doesn't fit in memory, but vectorize inside
  each chunk.
- **Preallocate** instead of appending to lists and calling `np.array` at the end, when sizes are known.
- **Mind temporaries.** `a * b + c` creates an intermediate array. For huge arrays, in-place operations (`a *= b;
  a += c`) or `out=` arguments save memory. Don't do this prematurely; do it when `nbytes` says you must.
- **Contiguity matters** for some operations. `np.ascontiguousarray` fixes a strided array before a heavy loop.
- **Measure.** `%timeit` in IPython, or `timeit.timeit` in scripts. Your intuition about what's slow is wrong more
  often than you think. Mine too. That's 01.4.

## Things that will bite you

- `(n,)` vs `(n, 1)` broadcasting into `(n, n)`. Assert shapes.
- Modifying a view and corrupting the original array (or not modifying a copy you thought was a view).
- Integer division and integer overflow in integer arrays. Cast to float before arithmetic that could be large.
- `np.mean` of an empty array returns `nan` with a warning, not an error. Warnings get ignored. Check sizes.
- NaN propagates silently: one NaN in a column makes its `mean()` NaN. `np.nanmean` exists, but first ask *why*
  there's a NaN.

<summary>Answers</summary>

1. `(4, 3) + (3,)` -> `(4, 3)`. `(4, 3) + (4,)` -> error: aligned from the right, 3 vs 4. `(4, 1) + (1, 5)` ->

   `(2,)`: matmul treats a 1-D first argument as a row vector and drops that dimension afterwards.

2. ```python
   def softmax(z):
       z = z - z.max(axis=-1, keepdims=True)   # softmax is invariant to shifting all inputs by a constant
       e = np.exp(z)
       return e / e.sum(axis=-1, keepdims=True)
   ```
   Subtracting the max makes the largest exponent `exp(0) = 1`, so nothing overflows, and since
   $\frac{e^{z_i - c}}{\sum_j e^{z_j - c}} = \frac{e^{z_i}}{\sum_j e^{z_j}}$, the result is identical.

3. ```python
   Xc = X - X.mean(axis=0)
   C = Xc.T @ Xc / (len(X) - 1)
   np.testing.assert_allclose(C, np.cov(X, rowvar=False))
   ```
   Dividing by $n-1$ (Bessel's correction) makes the sample covariance an *unbiased* estimator of the population
   covariance, because we used the sample mean, estimated from the same data, which is on average closer to the
   points than the true mean. Module 05.1 derives it.

4. `np.eye(k)[labels]`: fancy-index the rows of the identity matrix. (Alternative: `(labels[:, None] == np.arange(k)).astype(float)`, which is the broadcasting version and uses less memory for large k.)

5. `a[::2]` can be described by the same memory with a doubled stride (e.g. 16 instead of 8 bytes), so NumPy returns
   a view. `a[[0, 2, 4]]` picks arbitrary positions; in general (think `a[[4, 0, 0, 3]]`) no single stride can describe
   the result, so NumPy must copy the selected elements into new memory. It copies even when the indices happen to
   be regularly spaced, because it doesn't check.
