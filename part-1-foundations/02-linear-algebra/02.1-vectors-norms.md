# 02.1 Vectors, dot products and norms

*About 10 hours. Prerequisites: high school algebra, 01.3. Lab: [`lab_02_1_vectors.py`](labs/lab_02_1_vectors.py).*

When I tell people that most of machine learning is linear algebra, they usually nod politely and think I'm
exaggerating. So here's a list of things you'll do in this course that are, underneath, just dot products: a
linear regression prediction, a neuron's pre-activation, a similarity score in semantic search, an attention
weight in a transformer, a recommendation score, a projection in PCA, a kernel evaluation in an SVM. That's
not a coincidence. The dot product is the basic operation that measures "how much does this thing point in the
direction of that thing", and almost every model is built from that question.

This module is not a replacement for a full linear algebra course. It's the part of linear algebra you need
for ML, taught with geometry first, then algebra, then code, because that's the order in which it sticks.

## Vectors: two views that you need to hold at the same time

A vector $x \in \mathbb{R}^d$ is an ordered list of $d$ real numbers:

$$x = (x_1, x_2, \ldots, x_d)$$

You'll use two mental pictures, constantly switching between them:

1. **A point** (or an arrow from the origin) in $d$-dimensional space. A customer with 3 features (age, income,
   tenure) is a point in $\mathbb{R}^3$. An image with 784 pixels is a point in $\mathbb{R}^{784}$. A word
   embedding is a point in $\mathbb{R}^{768}$.
2. **A list of attributes**, one per coordinate. This is the database-row view.

Geometry works in any dimension, even when you can't picture it. The trick everybody uses (and it's legitimate) is
to reason in 2D or 3D and trust that the algebra carries over. Most of the time it does. When it doesn't, it
fails in very specific ways, and module 16.3 is about exactly those ways (the curse of dimensionality).

Convention: in this course vectors are **column vectors** unless said otherwise, and $x^\top$ is the row version.
In NumPy a 1-D array has no row/column orientation at all, which is convenient and occasionally confusing
(see the `(n,)` vs `(n, 1)` bug in 01.3).

## Operations

Addition and scaling work coordinate by coordinate:

$$x + y = (x_1 + y_1, \ldots, x_d + y_d), \qquad \alpha x = (\alpha x_1, \ldots, \alpha x_d)$$

Geometrically: addition puts arrows tip to tail; scaling stretches (or flips, if $\alpha < 0$).

A **linear combination** of vectors $v_1, \ldots, v_k$ is $\alpha_1 v_1 + \cdots + \alpha_k v_k$. The set of all linear
combinations is their **span**. If none of the vectors can be written as a combination of the others, they're
**linearly independent**. A set of $d$ independent vectors in $\mathbb{R}^d$ is a **basis**: every vector in the
space is a unique combination of them.

Why you care: a linear model's prediction $\hat{y} = w_1 x_1 + \cdots + w_d x_d$ is a linear combination of features.
If two features are linearly dependent (say, price in dollars and price in euros at a fixed rate), the model
can't tell how to split the weight between them, and the solution becomes unstable. That's **multicollinearity**,
and you'll see it bite in 02.3 and 17.1.

## The dot product

$$x \cdot y = x^\top y = \sum_{i=1}^{d} x_i y_i$$

The algebraic definition is a sum of products. The geometric meaning is the important one:

$$x^\top y = \|x\|\,\|y\|\cos\theta$$

where $\theta$ is the angle between the vectors. So the dot product is large and positive when the vectors point
in similar directions, zero when they're perpendicular (**orthogonal**), and negative when they point in opposite
directions.

Another way to see it: if $u$ is a unit vector, $u^\top x$ is the **length of the shadow** of $x$ on the line
along $u$, the scalar projection. The vector projection is:

$$\operatorname{proj}_u(x) = (u^\top x)\,u \qquad \text{and for a general } v: \quad \operatorname{proj}_v(x) = \frac{v^\top x}{v^\top v}\,v$$

This "shadow" picture is the key to linear regression (02.3), PCA (21.3) and attention (29.1). A linear model
$w^\top x$ projects each data point onto the direction $w$ and reads off the coordinate. A neuron does the same,
then bends the result with a nonlinearity.

## Norms: how big is a vector?

A norm measures length. The ones you'll meet:

$$\|x\|_2 = \sqrt{\sum_i x_i^2} \quad (\text{Euclidean, } L_2) \qquad \|x\|_1 = \sum_i |x_i| \quad (\text{Manhattan, } L_1) \qquad \|x\|_\infty = \max_i |x_i|$$

and the general $L_p$ norm $\|x\|_p = \left(\sum_i |x_i|^p\right)^{1/p}$ for $p \ge 1$.

Each defines a different "unit ball", the set of vectors with norm at most 1: a circle for $L_2$, a diamond for
$L_1$, a square for $L_\infty$. That picture explains one of the most useful facts in ML: **$L_1$ regularization
produces sparse solutions** (many exact zeros) because the diamond has corners on the axes, and an optimization
contour tends to touch the diamond at a corner. $L_2$ regularization shrinks everything a bit but rarely to
exactly zero. You'll see this properly in 17.2. Keep the diamond in your head until then.

Properties every norm satisfies: $\|x\| \ge 0$ with equality only for $x = 0$; $\|\alpha x\| = |\alpha|\,\|x\|$; and the
**triangle inequality** $\|x + y\| \le \|x\| + \|y\|$.

The **Cauchy-Schwarz inequality** $|x^\top y| \le \|x\|_2\,\|y\|_2$ is what guarantees that $\cos\theta$ stays between -1
and 1. It's also used in a surprising number of proofs in learning theory.

Distances come from norms: $d(x, y) = \|x - y\|$. Euclidean distance is $L_2$, Manhattan is $L_1$. Which one to use
for k-NN or clustering is a modeling decision, not a detail (19.1).

## Cosine similarity

$$\cos(x, y) = \frac{x^\top y}{\|x\|_2\,\|y\|_2}$$

Cosine similarity ignores length and compares only direction. It's the default similarity for text embeddings,
because the direction encodes meaning while the length is influenced by things like document length or word
frequency. If you **normalize** all vectors to unit length first, cosine similarity is just the dot product, which
is why vector databases often store normalized embeddings and use a plain inner product (41.1).

A relationship that comes up all the time: for unit vectors,

$$\|x - y\|_2^2 = \|x\|^2 + \|y\|^2 - 2x^\top y = 2 - 2\cos(x, y)$$

so ranking by Euclidean distance and ranking by cosine similarity give **the same order** for normalized vectors.
Knowing this saves you from a lot of pointless debates about which metric a vector index "should" use.

## Orthogonality and orthonormal bases

Vectors are orthogonal if $x^\top y = 0$. A set of mutually orthogonal unit vectors is **orthonormal**. The standard
basis $e_1 = (1, 0, \ldots), e_2 = (0, 1, 0, \ldots), \ldots$ is the obvious one, but there are infinitely many.

Orthonormal bases are wonderful because coordinates become dot products. If $u_1, \ldots, u_d$ is orthonormal,
then any $x$ is

$$x = \sum_{i=1}^{d} (u_i^\top x)\,u_i$$

No system of equations to solve, just $d$ dot products. PCA (21.3) is exactly "find a good orthonormal basis
for your data, and keep only the first few coordinates". The Fourier transform is the same idea with a different
basis. Whenever you see a "change of basis", think "rotating the coordinate system to one where the problem is
easier".

### Gram-Schmidt

Given independent vectors, the Gram-Schmidt process builds an orthonormal basis for their span: take each vector,
subtract its projections on the previous (already orthonormal) ones, normalize what's left.

```python
def gram_schmidt(V):
    """V: (k, d) array of k independent vectors -> (k, d) orthonormal rows spanning the same space."""
    Q = []
    for v in V:
        w = v - sum((q @ v) * q for q in Q)    # remove components along previous directions
        norm = np.linalg.norm(w)
        if norm < 1e-10:
            raise ValueError("vectors are (numerically) linearly dependent")
        Q.append(w / norm)
    return np.array(Q)
```

This is a teaching implementation. It's numerically fragile (rounding errors accumulate and the vectors slowly
lose orthogonality); real code uses the QR decomposition (`np.linalg.qr`), which you'll meet in 02.3. The lab lets
you watch the fragility happen.

## Vectors in high dimensions: a first warning

Two facts that will matter later and that your 3D intuition gets wrong:

1. **Random vectors in high dimensions are almost orthogonal.** Draw two random Gaussian vectors in
   $\mathbb{R}^{1000}$ and their cosine similarity is almost always within about $\pm 0.1$ of zero. In 2D it can
   be anything. This is why a cosine similarity of 0.3 between two embeddings might actually be meaningful.
2. **Distances concentrate.** In high dimensions, the distance from a point to its nearest neighbor and to its
   farthest neighbor become almost the same, relative to their size. That's a problem for any method based on
   "nearby points are similar" (k-NN, clustering, RBF kernels), and it's one face of the curse of dimensionality
   (16.3).

The lab measures both. Don't trust me, run it.

## Things that will bite you

- **Scale matters for distances and dot products.** If one feature is income in dollars (tens of thousands) and
  another is age in years (tens), Euclidean distance is basically "difference in income". Standardize features
  before any distance-based method (22.1).
- **Cosine similarity of the zero vector is undefined** (division by zero). Empty documents produce zero vectors.
  Guard against it.
- **Normalized vs unnormalized embeddings.** If you compute dot products on unnormalized embeddings thinking
  they're cosines, longer vectors win. Check the norm distribution of your embeddings before building an index.

## Exercises

1. Show that for any vectors, $\|x + y\|_2^2 = \|x\|_2^2 + \|y\|_2^2 + 2x^\top y$. What does this become when $x \perp y$?
   (You know this theorem by another name.)
2. Compute, by hand, the projection of $x = (3, 4)$ onto $v = (1, 0)$ and onto $v = (1, 1)$. Draw both.
3. For $x = (1, -2, 3)$, compute $\|x\|_1$, $\|x\|_2$ and $\|x\|_\infty$. Then prove that
   $\|x\|_\infty \le \|x\|_2 \le \|x\|_1$ for any vector.
4. Prove that for unit vectors, sorting candidates by increasing Euclidean distance to a query gives the same order
   as sorting by decreasing cosine similarity.
5. Why does linear independence of the features matter for a linear model? Construct a 3-feature dataset where
   two different weight vectors give *identical* predictions on every data point.

1. $\|x + y\|^2 = (x+y)^\top(x+y) = x^\top x + x^\top y + y^\top x + y^\top y = \|x\|^2 + 2x^\top y + \|y\|^2$. If
   $x \perp y$, the cross term vanishes: Pythagoras' theorem, in any dimension.

2. Onto $(1, 0)$: $\frac{3}{1}(1, 0) = (3, 0)$, the shadow on the x-axis. Onto $(1, 1)$:
   $\frac{3 + 4}{2}(1, 1) = (3.5, 3.5)$. The residual $x - (3.5, 3.5) = (-0.5, 0.5)$ is orthogonal to $(1, 1)$: check,
   $-0.5 + 0.5 = 0$. That orthogonal residual is the whole idea behind least squares (02.3).

3. $\|x\|_1 = 6$, $\|x\|_2 = \sqrt{14} \approx 3.74$, $\|x\|_\infty = 3$. Proof sketch: let $m = \max_i |x_i|$. Then
   $\|x\|_2^2 = \sum x_i^2 \ge m^2$, so $\|x\|_2 \ge \|x\|_\infty$. And
   $\|x\|_1^2 = (\sum |x_i|)^2 = \sum x_i^2 + \sum_{i \ne j} |x_i||x_j| \ge \sum x_i^2 = \|x\|_2^2$.

4. For unit vectors $\|q - x\|^2 = 2 - 2\cos(q, x)$, which is a strictly decreasing function of the cosine. A strictly
   monotone transformation preserves order (reversing it, since it's decreasing).

5. If features are linearly dependent, say $x_3 = x_1 + x_2$ for every row, then $w = (1, 1, 0)$ and $w' = (0, 0, 1)$
   give $w^\top x = x_1 + x_2 = x_3 = w'^\top x$ for every point. Infinitely many weight vectors fit the data
   equally well, so the "coefficients" are meaningless and the numerical solution becomes unstable. In practice the
   dependence is rarely exact; it's *nearly* exact (highly correlated features), which is worse, because nothing
   errors out, the coefficients just become huge and flip sign between runs.
