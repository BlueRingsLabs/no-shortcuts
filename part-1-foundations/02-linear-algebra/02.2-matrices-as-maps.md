# 02.2 Matrices as functions: multiplication, rank, inverses

*About 12 hours. Prerequisites: 02.1. Lab: [`lab_02_2_matrices.py`](labs/lab_02_2_matrices.py).*

At school, a matrix is a table of numbers and matrix multiplication is a weird ritual with rows and columns that
you memorize for the exam. That view is useless for ML. The view that makes everything click is this: **a matrix
is a function**. An $m \times n$ matrix $A$ takes a vector in $\mathbb{R}^n$ and returns a vector in
$\mathbb{R}^m$, and it does it *linearly*. A neural network layer is one of these functions followed by a
nonlinearity. A transformer is a few hundred of them stacked. Once you see matrices as functions, questions like
"can I undo this?", "what information does this destroy?" and "how sensitive is this to noise?" have geometric
answers.

## Linear maps

A function $f: \mathbb{R}^n \to \mathbb{R}^m$ is **linear** if

$$f(x + y) = f(x) + f(y) \quad \text{and} \quad f(\alpha x) = \alpha f(x)$$

Every linear map can be written as a matrix, and every matrix is a linear map. Here's why: write $x$ in the
standard basis, $x = x_1 e_1 + \cdots + x_n e_n$. By linearity,

$$f(x) = x_1 f(e_1) + \cdots + x_n f(e_n)$$

So $f$ is completely determined by what it does to the $n$ basis vectors. Put those $n$ output vectors as the
columns of a matrix $A$, and $f(x) = Ax$. That's the whole construction.

**The columns of $A$ are where the basis vectors land.** Remember that sentence and half of linear algebra
becomes visual. A rotation by 90° in 2D sends $e_1 = (1, 0)$ to $(0, 1)$ and $e_2 = (0, 1)$ to $(-1, 0)$, so

$$R = \begin{pmatrix} 0 & -1 \\ 1 & 0 \end{pmatrix}$$

## Matrix-vector multiplication, two ways

For $A \in \mathbb{R}^{m \times n}$ and $x \in \mathbb{R}^n$:

**Row view** (dot products): each output coordinate is the dot product of a row of $A$ with $x$.

$$(Ax)_i = a_i^\top x \qquad (a_i^\top \text{ is row } i)$$

This is how you compute it, and it's the "each row is a neuron / a linear classifier / a query" view.

**Column view** (linear combination): the output is a combination of the columns, weighted by the entries of $x$.

$$Ax = x_1 A_{:,1} + x_2 A_{:,2} + \cdots + x_n A_{:,n}$$

This is how you *think* about it. The set of all possible outputs $Ax$ is the span of the columns, the
**column space** (or range) of $A$.

## Matrix multiplication is composition

$AB$ is the function "first apply $B$, then apply $A$". That's why it's defined the way it is, and why the inner
dimensions must match: $B$ outputs vectors of the size that $A$ takes as input.

$$(AB)x = A(Bx), \qquad A \in \mathbb{R}^{m \times k},\; B \in \mathbb{R}^{k \times n},\; AB \in \mathbb{R}^{m \times n}$$

Consequences:

- **It's not commutative.** $AB \ne BA$ in general. Rotating then scaling along x is not the same as scaling then
  rotating. Try it on paper.
- **It's associative.** $(AB)C = A(BC)$. Same result, but *not* the same cost. For $A$: 1000x1000, $B$: 1000x1000,
  $x$: 1000x1, computing $(AB)x$ costs about $10^9$ multiplications, while $A(Bx)$ costs about $2 \times 10^6$. Order
  your products. Autograd engines (24.3) and the trick behind efficient backprop both rely on this.
- **A stack of linear layers is just one linear layer.** $W_3 W_2 W_1 x = (W_3 W_2 W_1)x = Wx$. Without
  nonlinearities between them, a 100-layer "deep" network is exactly as expressive as linear regression. That's the
  single most important reason neural networks need activation functions (24.1).

Cost: multiplying $m \times k$ by $k \times n$ takes $mkn$ multiply-adds, $2mkn$ FLOPs. You'll use this formula to
estimate the cost of training a transformer in 33.1. Seriously, keep it.

## Rank, column space and null space

The **rank** of $A$ is the dimension of its column space: how many independent directions its outputs can span.
It's also, always, the number of independent rows. For $A \in \mathbb{R}^{m \times n}$, $\operatorname{rank}(A) \le \min(m, n)$.

The **null space** is the set of inputs that $A$ sends to zero: $\{x : Ax = 0\}$. These are the directions $A$
destroys.

The **rank-nullity theorem** ties them together:

$$\operatorname{rank}(A) + \dim(\operatorname{null}(A)) = n$$

Every input dimension either survives (contributes to the output) or is destroyed. Nothing else can happen.

Why an ML engineer cares:

- If your design matrix $X$ (rows = samples, columns = features) has rank less than the number of features, some
  combination of features is in the null space: you can change the weights along that direction and the
  predictions don't change. The model is not **identifiable**. That's multicollinearity again (02.1, 17.1).
- A projection onto a line in 3D has rank 1 and a 2D null space: everything perpendicular to the line is lost. You
  cannot recover a 3D point from its shadow. Information destroyed by a rank-deficient map is gone for good.
- **Low-rank** matrices are cheap to store and apply. A $d \times d$ matrix of rank $r$ can be written as
  $UV^\top$ with $U, V \in \mathbb{R}^{d \times r}$: $2dr$ numbers instead of $d^2$. That's exactly the idea behind
  LoRA (38.2), which fine-tunes LLMs by learning a low-rank update to each weight matrix. And behind matrix
  factorization recommenders (23.2). And the SVD (02.4) tells you the best low-rank approximation of any matrix.

## Inverses

A square matrix $A \in \mathbb{R}^{n \times n}$ is **invertible** if there's $A^{-1}$ with $A^{-1}A = AA^{-1} = I$.
Geometrically: the map can be undone. That's possible exactly when nothing is destroyed, which means all of these
equivalent conditions:

- $\operatorname{rank}(A) = n$ (full rank),
- the null space is just $\{0\}$,
- the columns are linearly independent,
- $\det(A) \ne 0$,
- $Ax = b$ has exactly one solution for every $b$.

Useful identities: $(AB)^{-1} = B^{-1}A^{-1}$ (undo in reverse order: to undo "socks then shoes", remove shoes
first) and $(A^\top)^{-1} = (A^{-1})^\top$.

### The determinant, briefly

$\det(A)$ is the factor by which $A$ scales volumes (areas in 2D), with a sign that says whether it flips
orientation. $\det = 0$ means some dimension gets squashed flat, so volume becomes zero and the map can't be
inverted. You'll need determinants for the Gaussian density (04.1) and for normalizing flows (31.4). You'll almost
never compute one by hand, and you should never use "the determinant is small" as a test for "almost singular":
$\det(0.1 I_{100}) = 10^{-100}$, and that matrix is perfectly well-behaved. Use the condition number instead.

### Never invert a matrix to solve a system

This is a rule I'll repeat until you're sick of it. To solve $Ax = b$:

```python
x = np.linalg.solve(A, b)      # yes: LU factorization, stable, about n^3/3 flops
x = np.linalg.inv(A) @ b       # no: about 3x the work and less accurate
```

Computing the inverse explicitly does more work *and* introduces more rounding error than solving directly. And
for least squares problems (non-square $A$), use `np.linalg.lstsq` or QR (02.3), not the normal equations with an
inverse. The only time you want $A^{-1}$ explicitly is when you actually need its entries, which is rare.

## Conditioning: how sensitive is the answer?

Some systems are fragile: tiny changes in $b$ (noise in your data) cause huge changes in $x$. The **condition
number** measures this:

$$\kappa(A) = \|A\|\,\|A^{-1}\| = \frac{\sigma_{\max}(A)}{\sigma_{\min}(A)}$$

(the second form uses singular values, 02.4). Rule of thumb: you lose about $\log_{10}\kappa(A)$ decimal digits of
accuracy when solving $Ax = b$. With float64 you have about 16 digits. With $\kappa = 10^{12}$, your answer has
about 4 correct digits. With $\kappa = 10^{16}$, none.

Geometrically, an ill-conditioned matrix squashes some direction almost (but not quite) flat. Undoing that requires
stretching that direction back by a huge factor, which also stretches any noise in that direction.

Where you meet it in ML: nearly collinear features make $X^\top X$ ill-conditioned (its condition number is the
*square* of $X$'s, which is exactly why the normal equations are a bad idea, 02.3). Badly scaled features do it too.
Ridge regression (17.2) is, among other things, a fix for conditioning: adding $\lambda I$ to $X^\top X$ raises the
smallest eigenvalue and caps the condition number.

## A zoo of special matrices

You'll meet these again and again:

| Matrix | Definition | Geometric meaning | Where you see it |
|---|---|---|---|
| Diagonal | only $A_{ii} \ne 0$ | scale each axis independently | feature scaling, Adam's per-parameter step sizes |
| Orthogonal $Q$ | $Q^\top Q = I$ | rotation/reflection, preserves lengths and angles | PCA bases, QR, orthogonal init (26.2) |
| Symmetric | $A = A^\top$ | stretches along orthogonal axes (02.4) | covariance matrices, Hessians, kernels |
| Positive semidefinite (PSD) | symmetric and $x^\top A x \ge 0$ for all $x$ | "bowl-shaped" quadratic form | covariances, kernel matrices, $X^\top X$ |
| Projection $P$ | $P^2 = P$ | flatten onto a subspace; applying twice changes nothing | least squares (02.3) |
| Triangular | zeros above (or below) the diagonal | solvable by substitution, cheap | LU, Cholesky, causal attention masks |

Orthogonal matrices deserve a special mention: $Q^{-1} = Q^\top$, so inverting them is free, and they have condition
number exactly 1, so they never amplify errors. Numerical algorithms love them for that reason.

$X^\top X$ is always PSD: $v^\top X^\top X v = \|Xv\|^2 \ge 0$. So is any covariance matrix. If you ever compute a
"covariance matrix" with a negative eigenvalue, it's a bug or a rounding problem, and it will break things like
Cholesky decompositions and Gaussian sampling downstream.

## Things that will bite you

- **Order of multiplication**: `A @ B` vs `B @ A`, and parenthesization for cost. Write the shapes in a comment.
- **`*` vs `@`** in NumPy and PyTorch: `*` is elementwise, `@` is matrix product. Mixing them up with square
  matrices gives no error and a wrong answer.
- **Inverting matrices.** `solve`, `lstsq`, `cho_solve`. Not `inv`.
- **Trusting small determinants** as a singularity test. Use `np.linalg.cond` or look at singular values.

2. Show that if $W_1 \in \mathbb{R}^{64 \times 784}$ and $W_2 \in \mathbb{R}^{10 \times 64}$, the composed map $W_2 W_1$

3. You have $A \in \mathbb{R}^{2000 \times 2000}$, $B \in \mathbb{R}^{2000 \times 2000}$ and $v \in \mathbb{R}^{2000}$.
   Count the FLOPs of $(AB)v$ and $A(Bv)$.
4. Show that for an orthogonal $Q$, $\|Qx\|_2 = \|x\|_2$ for every $x$.
5. Construct a 2x2 matrix with determinant $10^{-10}$ and condition number 1, and one with determinant 1 and condition
   number $10^{10}$.
