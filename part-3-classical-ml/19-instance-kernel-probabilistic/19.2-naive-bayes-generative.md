# 19.2 Naive Bayes and generative classifiers

*About 7 hours. Prerequisites: 04.2 (Bayes' rule), 04.4 (MLE, MAP), 17.3, 18.3. Lab: [`lab_19_2_generative.py`](labs/lab_19_2_generative.py).*

Every classifier so far has modeled $P(y \mid x)$ directly: given the features, what's the label? That's the **discriminative** approach. There's
another way to build a classifier, older and in some ways more natural: model how each class *generates* its data, $p(x \mid y)$, model how common
each class is, $P(y)$, and get the classifier from Bayes' rule:

$$P(y = c \mid x) = \frac{p(x \mid y = c)\,P(y = c)}{\sum_{c'} p(x \mid y = c')\,P(y = c')}$$

That's the **generative** approach. It asks you to model more than you need (the full distribution of the features, when you only wanted a
boundary), which sounds wasteful, and often is. But it buys things discriminative models can't give you easily: handling missing features,
adapting to a new class balance by changing one number, detecting inputs unlike anything in any class, learning from very little data. And the
generative idea, scaled up with neural networks, is what VAEs, diffusion models and language models are (31.1 to 31.4, 35.2). A language model is a
generative model of text. It's worth understanding the idea in its simplest form.

## Naive Bayes

The full $p(x \mid y)$ in $d$ dimensions is hard to estimate. Naive Bayes makes it trivial with one bold assumption: **features are conditionally independent given the class**,

$$p(x \mid y = c) = \prod_{j=1}^d p(x_j \mid y = c)$$

so you only need $d$ one-dimensional distributions per class. Fit each by maximum likelihood (counts and means), and classify by

$$\hat y = \arg\max_c \Big[\log P(y = c) + \sum_j \log p(x_j \mid y = c)\Big]$$

(always in log space: a product of hundreds of small probabilities underflows to zero, 07.2). Training is one pass over the data. Prediction is a sum.

Variants, by the distribution chosen for each feature:

- **Gaussian NB**: $x_j \mid y = c \sim \mathcal{N}(\mu_{cj}, \sigma^2_{cj})$. Continuous features.
- **Multinomial NB**: features are counts (word counts in a document), $p(x \mid c) \propto \prod_j \theta_{cj}^{x_j}$, with $\theta_{cj}$ the probability of word $j$ in class $c$. The classic
  text classifier.
- **Bernoulli NB**: binary features (word present or not). Also counts absences as evidence, which helps for short texts.
- **Categorical NB**: one categorical distribution per feature.

### Smoothing

Estimate $\theta_{cj}$ as the fraction of class-$c$ words that are word $j$, and a word that never appeared in a spam training email gets probability zero. One such word
in a new email makes $p(x \mid \text{spam}) = 0$, whatever the other thousand words say. The fix is **Laplace (additive) smoothing**:

$$\hat\theta_{cj} = \frac{N_{cj} + \alpha}{N_c + \alpha d}$$

with $\alpha = 1$ as the classic choice. It's MAP estimation with a symmetric Dirichlet prior (04.4), "pretend you saw every word $\alpha$ extra times". Tune $\alpha$ by
cross-validation; for large vocabularies, values well below 1 often work better.

### Why it works when the assumption is false

The independence assumption is almost always wrong. Words aren't independent ("San" and "Francisco"); pixel values aren't; medical measurements aren't. Yet naive
Bayes classifies surprisingly well, and for a long time it was the spam filter. The explanation (Domingos and Pazzani, 1997): classification only needs the
**right argmax**, not the right probabilities. Correlated features get double-counted, which pushes the posterior toward 0 or 1, but often in the right direction.

So: **the ranking and the decisions can be good while the probabilities are terrible**. Naive Bayes is the textbook case of overconfidence (18.3). If you
duplicate a feature, naive Bayes counts its evidence twice; duplicate it ten times and the probabilities slam into 0 and 1 while the accuracy barely moves. The
lab does exactly that. Recalibrate if you need probabilities.

Where naive Bayes is still a good choice: text classification baselines (fast, strong with little data), very high-dimensional sparse features, streaming
settings (updating counts is trivial), and as a sanity check for any fancier text model. If your transformer doesn't beat multinomial NB with TF-IDF-ish features on
your data, look hard at your transformer.

## Gaussian discriminant analysis: LDA and QDA

Drop the independence assumption and model each class as a full multivariate Gaussian, $x \mid y = c \sim \mathcal{N}(\mu_c, \Sigma_c)$.

**LDA** (linear discriminant analysis) assumes all classes **share one covariance** $\Sigma$. Then the quadratic terms cancel in the log-odds, and

$$\log\frac{P(y = 1 \mid x)}{P(y = 0 \mid x)} = x^\top\Sigma^{-1}(\mu_1 - \mu_0) + \text{const}$$

is **linear in $x$**: the posterior is exactly a logistic function (17.3). LDA and logistic regression have the same functional form. They differ in how they fit it:
logistic regression maximizes the conditional likelihood $\prod_i P(y_i \mid x_i)$ directly; LDA estimates means and a pooled covariance and plugs them in. If the Gaussian
assumption holds, LDA uses the data more efficiently. If it doesn't (heavy tails, outliers, categorical features), logistic regression is more robust, because it
never assumed anything about $p(x)$.

**QDA** gives each class its own $\Sigma_c$: the boundary becomes quadratic. More flexible, and $d(d+1)/2$ covariance parameters *per class*, so it needs a lot more data. Regularized
discriminant analysis shrinks the covariances toward a shared one, or toward the diagonal (which is Gaussian naive Bayes), interpolating between the three models.

LDA is also a **supervised dimensionality reduction**: project onto the (at most $K - 1$) directions that best separate the class means relative to the within-class
spread (Fisher's discriminant). Handy for visualization, and a contrast with PCA (21.3), which ignores the labels.

## Generative vs discriminative

Ng and Jordan (2001) compared naive Bayes with logistic regression, a generative-discriminative pair with the same functional form, and found a clean pattern:

- The **generative** model converges to *its* asymptotic error much faster (it needs on the order of $\log d$ examples, against order $d$ for the discriminative model).
- The **discriminative** model has a *lower* asymptotic error when the generative assumptions are wrong, which they usually are.

So with little data, generative often wins; with plenty, discriminative wins. The lab reproduces the crossover, and adds the modern footnote: Ng and Jordan
compared against *unregularized* logistic regression. Give the discriminative model a sensible L2 penalty (17.2) and most of the generative model's small-sample
advantage disappears. Regularization is, in effect, the discriminative model borrowing the generative model's humility. Other trade-offs:

| | Generative ($p(x \mid y)P(y)$) | Discriminative ($P(y \mid x)$) |
|---|---|---|
| Missing features at prediction time | marginalize them out (for NB: drop their terms) | need imputation |
| Class prior changes | change $P(y)$, done (18.3) | recalibrate the intercept |
| Detect inputs unlike any class | low $p(x)$ under every class | no built-in notion |
| Unlabeled data | can use it (EM, 21.2) | mostly can't |
| Wrong assumptions about $p(x)$ | hurt accuracy | don't matter |
| Calibrated probabilities | often poor (NB) | usually better |

The modern synthesis: discriminative models for prediction, generative models when you need to generate, detect novelty, or use unlabeled data, and deep generative
models (Module 31) that make "model $p(x)$" feasible for images and text.

## Things that will bite you

- **Zero counts** without smoothing.
- **Multiplying probabilities** instead of adding logs.
- **Reading naive Bayes probabilities** as calibrated.
- **Redundant features** (many near-copies) amplifying NB's overconfidence.
- **QDA with few examples per class** and many features: singular covariance estimates. Regularize.
- **Gaussian NB on heavily skewed features**: transform them first (log), or use a different per-feature distribution.

1. $\log p(x \mid c) = -\frac{1}{2}(x - \mu_c)^\top\Sigma^{-1}(x - \mu_c) + \text{const}$. Subtract for $c = 1, 0$: the $x^\top\Sigma^{-1}x$ terms cancel because $\Sigma$ is shared, leaving

   boundary is quadratic.

2. $\hat\theta_{\text{ham},\text{invoice}} = 0$, so $p(x \mid \text{ham}) = 0$ and the email is classified as spam (if "invoice" appeared in spam training emails) no matter what else it
   contains. With smoothing, $\hat\theta = \alpha / (N_{\text{ham}} + \alpha d) > 0$: the word counts as weak evidence, not a veto.

3. The class-conditional log-likelihood of each feature is counted twice, so the log-odds (apart from the prior term) double. The argmax is unchanged when the prior is
   uniform (and usually otherwise); the probabilities become far more extreme. Overconfidence from double-counting evidence.

4. $p(x_{\text{observed}} \mid c) = \prod_{j \text{ observed}} p(x_j \mid c)$: the missing feature is integrated out, which for NB just means dropping its factor. Logistic regression's
   $P(y \mid x)$ needs every input; to marginalize it you'd need a model of $p(x_{\text{missing}} \mid x_{\text{observed}})$, which it doesn't have, so you impute.

5. The generative model estimates a few low-dimensional quantities per class (means, variances, counts), each from all the class's data, and each converges at the usual
   $1/\sqrt{n}$ rate independently. The discriminative model fits the boundary jointly across all parameters and needs enough data to pin down all of them at once.
   The price for the generative model's speed is bias when its assumptions are wrong.
