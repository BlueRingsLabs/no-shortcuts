# 22.3 Interpretability: permutation importance, PDP, SHAP

*About 9 hours. Prerequisites: 20.1 (impurity importance and its bias), 20.4, 18.4, 05.4 (causal inference). Lab: [`lab_22_3_interpretability.py`](labs/lab_22_3_interpretability.py).*

Sooner or later someone will ask your model "why?". Why was this loan declined? Which features drive churn? Is the model relying on something it shouldn't?
Sometimes the someone is a regulator, and the answer has legal weight: credit decisions in many jurisdictions require the reasons for an adverse outcome. More often
it's you, debugging: the fastest way to find 18.4's leakage is to look at what the model actually uses.

This lesson covers the three tools you'll use most (permutation importance, partial dependence, and SHAP values), how each is computed, and above all what each
**can't** tell you. The misuse is predictable: explanations get read as statements about the world ("income causes default") when they're statements about the model
("this model's output moves with income"). Keep those two apart and these tools are extremely useful.

## Kinds of explanation

- **Global** (how does the model behave overall?) vs **local** (why this prediction?).
- **Interpretable by design** (the model *is* the explanation: a linear model with sensible features, a small tree, a GAM or explainable boosting machine where the prediction is a sum of one-feature
  curves, a monotone-constrained GBDT) vs **post-hoc** (explain a black box after the fact). When the stakes are high and an interpretable model is nearly as accurate, use it (Rudin, 2019, makes
  the argument forcefully). The lab's first point of comparison is always "how far is a GAM-like model from the black box?".
- **Model-agnostic** (works on any model through its predictions) vs **model-specific** (exploits the structure, like TreeSHAP for trees).

## Permutation importance

For each feature: shuffle its column in the **held-out** data, re-score the model, and record how much the score drops. Repeat a few times and average. Big drop: the model relies on the feature.
Model-agnostic, directly in units of your metric, and on held-out data it can't be fooled by features the model merely overfit (unlike impurity importance, 20.1).

Limits:

- **Correlated features share and hide importance.** If $x_1$ and its near-copy $x_5$ both carry the signal, shuffling either one alone barely hurts, because the model can lean on the other. Both look
  unimportant while together they're essential. The lab shows it. Group correlated features and permute them together, or look at drop-column importance.
- **Shuffling creates impossible rows** (a 20-year-old with 30 years of employment) and asks the model about regions it never saw. With strongly dependent features, that answer is noise.
- **Drop-column importance** (retrain without the feature, compare scores) answers a different question: "how much would a model *without* this feature lose?", which includes what the other features can
  compensate. Expensive, and often closer to what people actually want to know.

## Partial dependence and ICE

The **partial dependence** of the prediction on feature $x_j$ is the average prediction when $x_j$ is set to a value $v$ for *every* row, as a function of $v$:

$$\text{PD}_j(v) = \frac{1}{n}\sum_i \hat f(v, x_{i, -j})$$

It shows the average shape of the model's response: monotone, threshold, saturating. **ICE curves** (individual conditional expectation) draw the same thing per row, before averaging. When the ICE curves
fan out or cross, the feature **interacts** with others and the average hides it: a PDP can be flat for a feature that pushes half the rows up and half down. The lab builds that case.

The PDP inherits permutation's problem: setting $x_j = v$ for every row creates impossible combinations when features are correlated. **Accumulated local effects** (ALE, Apley and Zhu, 2020) fix this
by averaging the model's *local change* within narrow bins of $x_j$, using only rows actually near each value, then accumulating. The lab implements a simple ALE and counts how many of
the PDP's evaluation rows are combinations that never occur in the data (most of them, for a correlated pair).

## SHAP values

For a single prediction, we want to split $\hat f(x) - \mathbb{E}[\hat f(X)]$ (this prediction minus the average one) into contributions $\phi_j$, one per feature. **Shapley values** from cooperative game theory
(Shapley, 1953) are the unique way to do that satisfying four reasonable axioms:

- **Efficiency**: the contributions add up exactly: $\sum_j \phi_j = \hat f(x) - \mathbb{E}[\hat f(X)]$.
- **Symmetry**: two features that contribute identically in every coalition get equal credit.
- **Dummy**: a feature that never changes the output gets zero.
- **Additivity**: for a sum of models, the contributions add.

The formula averages each feature's marginal contribution over all orders in which features could be "revealed":

$$\phi_j = \sum_{S \subseteq F \setminus \{j\}} \frac{|S|!\,(|F| - |S| - 1)!}{|F|!}\,\big[v(S \cup \{j\}) - v(S)\big]$$

where $v(S)$ is the model's expected output when only the features in $S$ are known. **SHAP** (Lundberg and Lee, 2017) is the family of methods that compute these for ML models.

Two things to understand about it:

- **Cost.** The sum has $2^{|F|}$ terms. **KernelSHAP** approximates it for any model by sampling coalitions and fitting a weighted linear model; slow and approximate. **TreeSHAP** computes it exactly for tree
  ensembles in polynomial time by walking the trees. That's why SHAP is so popular with gradient boosting (20.4). For a linear model with independent features, $\phi_j = \beta_j(x_j - \mathbb{E}[x_j])$, which
  the lab verifies, along with a brute-force Shapley computation matching TreeSHAP.
- **What "only the features in $S$ are known" means.** The **interventional** definition fills the unknown features from a background dataset independently of the known ones (breaking correlations,
  with the same impossible-rows issue as permutation); the **observational/conditional** one uses the conditional distribution (respects correlations, but can assign credit to features the model doesn't use,
  through their correlation with ones it does). They answer different questions and can disagree. Know which one your tool computes (TreeSHAP offers both).

Summaries: the mean $|\phi_j|$ over a dataset is a global importance; plotting $\phi_j$ against $x_j$ (a dependence plot) shows the shape and, through the vertical spread, the interactions.

## What these tools can't do

- **They explain the model, not the world.** A large SHAP value for income means *this model's* predictions move with income. Whether income *causes* default is a causal question (05.4) that no
  post-hoc explanation of a predictive model answers. The lab trains a model on a feature that's a *consequence* of the label and gets a huge, meaningless importance for it.
- **Correlated features make every method arbitrary** to some degree: credit gets split, shuffled away, or assigned through correlation, depending on the method. The lab retrains on bootstrap
  samples and shows the SHAP ranking of two correlated features swapping.
- **Explanations can be gamed.** Slack et al. (2020) built models that behave in a biased way on real inputs but look innocent to LIME and SHAP, which probe with off-distribution samples. An explanation
  is evidence, not an audit.
- **Local explanations aren't recourse.** "Your top negative factor was debt ratio" doesn't tell the applicant what change would flip the decision. **Counterfactual explanations** ("if your debt ratio were
  below 0.35, you'd be approved") answer that, with their own subtleties (actionable changes only, plausible combinations).

## Things that will bite you

- **Impurity importance** instead of held-out permutation importance.
- **Permutation importance with correlated features**, read one feature at a time.
- **A flat PDP** read as "no effect" when ICE curves would show an interaction.
- **SHAP values presented as causal effects**, especially in slides for executives.
- **Explaining a leaky model** and not noticing that the top feature is the leak (this is the good use: look for it).
- **Not saying which SHAP variant** (interventional or conditional, which background data) produced a number.
- **Tool defaults you didn't read**: the `shap` library silently subsamples an interventional background above 100 rows. The lab caught it by checking against a brute-force computation.

## Exercises

1. Two features are identical copies. What do permutation importance, drop-column importance and (interventional) SHAP each say about them?
2. Construct a model where the PDP of $x_1$ is flat but $x_1$ matters a lot. What do the ICE curves look like?
3. Show that for a linear model $\hat f(x) = \beta_0 + \sum_j\beta_jx_j$ with independent features, the Shapley value of feature $j$ is $\beta_j(x_j - \mathbb{E}[x_j])$.
4. Why is the efficiency axiom useful for explaining a single decision to a customer, and what's the catch in choosing the baseline $\mathbb{E}[\hat f(X)]$?
5. A SHAP analysis of a hiring model shows "years since graduation" has a large negative contribution for older candidates. What does this tell you, what doesn't it tell you, and what would you do?

1. Permutation: shuffling one copy barely hurts (the model uses the other), so both look unimportant. Drop-column: dropping one copy costs nothing (the other remains), so both look unimportant again,

3. $v(S) = \mathbb{E}[\hat f(X) \mid X_S = x_S] = \beta_0 + \sum_{k \in S}\beta_kx_k + \sum_{k \notin S}\beta_k\mathbb{E}[X_k]$ (independence). So $v(S \cup \{j\}) - v(S) = \beta_j(x_j - \mathbb{E}[X_j])$ for every $S$, and any weighted average of a constant is that constant.
