# 20.3 Boosting: from AdaBoost to gradient boosting

*About 10 hours. Prerequisites: 20.1, 20.2, 03.1 and 03.2 (gradients, Newton's method), 17.3 (log loss), 18.1. Lab: [`lab_20_3_boosting.py`](labs/lab_20_3_boosting.py).*

Bagging builds its trees independently and averages away their variance. **Boosting** builds them *sequentially*, each one trained to fix what the
ensemble so far gets wrong. It started as a theoretical question (Kearns and Valiant, 1988): can a pile of "weak learners", each barely better than
guessing, be combined into a strong one? Schapire proved yes in 1990; Freund and Schapire's AdaBoost (1997) made it practical; and Friedman's
gradient boosting (2001) turned it into a general optimization method that, in its modern implementations, is the best tool we have for tabular
data. If you enter a Kaggle competition on a table of features, you'll almost certainly end up with gradient-boosted trees, and in industry they
run credit decisions, fraud scoring, ranking, pricing and demand forecasting everywhere.

This lesson builds boosting from the ground up, because the derivation is short and understanding it tells you exactly what each hyperparameter
in XGBoost does (20.4).

## The additive model

Boosting fits a sum of simple functions (usually small trees):

$$F_M(x) = F_0(x) + \sum_{m=1}^M \nu\, h_m(x)$$

one term at a time: at step $m$, keep $F_{m-1}$ fixed and choose $h_m$ to improve the loss as much as possible. That's **forward stagewise additive modeling**. The weak learners
reduce **bias** by accumulating (each fixes some remaining structure), which is the opposite of bagging's job. And because each step fits the *training* data harder, running
too many steps overfits, which is the self-check question of this module.

## AdaBoost

The original, for binary labels $y \in \{-1, +1\}$:

1. Start with equal weights $w_i = 1/n$.
2. For $m = 1, \dots, M$: fit a weak classifier $h_m$ (often a stump) to the weighted data; compute its weighted error $\epsilon_m$; set $\alpha_m = \frac{1}{2}\log\frac{1 - \epsilon_m}{\epsilon_m}$;
   multiply the weights of misclassified points by $e^{\alpha_m}$ and of correct ones by $e^{-\alpha_m}$, then renormalize.
3. Predict $\text{sign}\big(\sum_m \alpha_m h_m(x)\big)$.

Hard examples get more weight each round, so later learners focus on them. It worked startlingly well, and for a while nobody quite knew why. Friedman, Hastie and Tibshirani
(2000) explained it: AdaBoost is forward stagewise additive modeling with the **exponential loss** $e^{-yF(x)}$. That also explained its weakness: the exponential loss punishes
confidently wrong points exponentially, so mislabeled examples get enormous weights and the model contorts itself to fit them. On noisy labels, AdaBoost suffers; the lab
shows it. The fix is to use a better loss, which requires a way to boost *any* loss.

## Gradient boosting

Think of the predictions on the training set, $F = (F(x_1), \dots, F(x_n))$, as the parameters, and minimize $L(F) = \sum_i \ell(y_i, F(x_i))$ by gradient descent (03.3). The steepest-descent
direction is the negative gradient, the **pseudo-residuals**:

$$r_{im} = -\left.\frac{\partial \ell(y_i, F)}{\partial F}\right|_{F = F_{m-1}(x_i)}$$

But a vector of $n$ numbers only tells you what to do at the training points. To get a function that generalizes, **fit a regression tree $h_m$ to the pseudo-residuals**, then take a
step: $F_m = F_{m-1} + \nu h_m$. Gradient descent in function space, with trees as the way to turn a gradient at $n$ points into a function everywhere. (Friedman, 2001.)

For each loss, the pseudo-residual is something familiar:

| Loss | $\ell(y, F)$ | Pseudo-residual $r$ |
|---|---|---|
| Squared | $\frac{1}{2}(y - F)^2$ | $y - F$: the ordinary residual |
| Absolute | $\lvert y - F\rvert$ | $\text{sign}(y - F)$ |
| Huber | quadratic near 0, linear beyond $\delta$ | residual, clipped at $\pm\delta$ |
| Log loss ($y \in \{0,1\}$, $F$ = log-odds) | $-[y\log p + (1-y)\log(1-p)]$, $p = \sigma(F)$ | $y - p$ (17.3's gradient) |
| Quantile $\tau$ | pinball loss (18.2) | $\tau$ if $y > F$, else $\tau - 1$ |
| Poisson (log link) | $e^F - yF$ | $y - e^F$ |

With squared loss, "fit a tree to the residuals, add it, repeat" is the whole algorithm, and the lab implements it in about ten lines and matches scikit-learn exactly.

**Leaf values.** The tree fitted to the pseudo-residuals decides the *regions*; the value in each leaf can then be optimized for the actual loss. Friedman uses one Newton step per leaf:
for log loss, leaf value $= \frac{\sum_{i \in \text{leaf}} (y_i - p_i)}{\sum_{i \in \text{leaf}} p_i(1 - p_i)}$. That's the gradient divided by the Hessian (03.2), which leads straight to XGBoost.

## The second-order view (XGBoost)

Chen and Guestrin (2016) made the Newton idea the center of the algorithm. Expand the loss to second order around the current predictions, with $g_i = \partial\ell/\partial F$ and
$h_i = \partial^2\ell/\partial F^2$, and add a regularizer on the tree: $\gamma$ per leaf and $\frac{\lambda}{2}\|w\|^2$ on the leaf values $w$. For a fixed tree structure, each leaf $j$ with example set $I_j$
contributes $G_j w_j + \frac{1}{2}(H_j + \lambda)w_j^2$ (with $G_j = \sum_{I_j} g_i$, $H_j = \sum_{I_j} h_i$), minimized at

$$w_j^* = -\frac{G_j}{H_j + \lambda}, \qquad \text{objective reduction} = \frac{1}{2}\frac{G_j^2}{H_j + \lambda}$$

and the **gain** of splitting a leaf into left and right children is

$$\text{Gain} = \frac{1}{2}\left[\frac{G_L^2}{H_L + \lambda} + \frac{G_R^2}{H_R + \lambda} - \frac{(G_L + G_R)^2}{H_L + H_R + \lambda}\right] - \gamma$$

Every split decision and every leaf value uses only sums of $g$ and $h$, so **any twice-differentiable loss** plugs in by supplying two formulas. The lab computes these by hand for a
one-split tree and checks them against XGBoost's own dumped tree. It's also where XGBoost's hyperparameters come from: `reg_lambda` is $\lambda$, `gamma` (or `min_split_loss`) is $\gamma$,
and `min_child_weight` is a minimum on $H_j$ (for log loss, roughly "minimum number of confidently-uncertain examples per leaf").

## The knobs, and why boosting overfits

- **Learning rate (shrinkage) $\nu$** and **number of rounds $M$**: a smaller step needs more rounds and almost always generalizes better (Friedman's empirical finding, and the lab's).
  Typical: $\nu$ between 0.01 and 0.1.
- **Early stopping**: because each round reduces the *training* loss, eventually the model is fitting noise and the validation loss rises (the self-check's answer, in contrast with
  20.2's forests). Monitor a validation set and stop when it hasn't improved for, say, 50 rounds. With early stopping, $M$ stops being a hyperparameter and $\nu$ becomes a compute-vs-accuracy
  dial.
- **Tree size** (`max_depth`, `num_leaves`): a tree of depth $k$ can represent interactions among up to $k$ features. Stumps (depth 1) give an **additive model** with no interactions at all;
  the lab shows stumps failing on a pure interaction that depth-2 trees capture. Typical depths: 3 to 8.
- **Subsampling** rows (`subsample`) and columns (`colsample_*`): stochastic gradient boosting (Friedman, 2002). Adds randomness that reduces variance and speeds things up, borrowed from forests.
- **Regularization** $\lambda$, $\gamma$, `min_child_weight`: shrink leaf values and forbid weak splits.

Tuning order that usually works: fix $\nu = 0.1$ and use early stopping; tune tree size and `min_child_weight`; then subsampling; then regularization; finally lower $\nu$ (and let early stopping
raise $M$) for the last bit of accuracy. 22.2 automates this.

## Why it wins on tables

Trees handle heterogeneous features, missing values and monotone transformations without preprocessing (20.1); boosting removes their bias; shrinkage, subsampling and
early stopping control their variance; second-order optimization makes any sensible loss available. Deep networks still struggle to beat well-tuned boosted trees on typical tabular
data (Grinsztajn et al., 2022). That result has held up surprisingly well.

## Things that will bite you

- **No early stopping**, or early stopping on the test set.
- **A learning rate of 0.3 or 1.0** because it's faster, then reporting the result as the model's best.
- **AdaBoost on noisy labels.**
- **Stumps when the problem needs interactions** (or deep trees when it doesn't).
- **Probabilities from boosted trees** without checking calibration (usually decent with log loss; check anyway, 18.3).
- **Extrapolation**, still impossible: it's a sum of trees.

## Exercises

1. Show that for squared loss the pseudo-residuals are the residuals, and for log loss with $F$ the log-odds they're $y - p$.
2. Derive the Newton leaf value $\sum(y_i - p_i) / \sum p_i(1 - p_i)$ for log loss.
3. Derive $w_j^* = -G_j/(H_j + \lambda)$ and the split gain formula from the second-order objective.
4. Why does AdaBoost's exponential loss make it sensitive to mislabeled examples, compared with log loss?
5. With early stopping on a validation set, why does a smaller learning rate usually give a better final model? What does it cost?

<summary>Answers</summary>

1. $\frac{\partial}{\partial F}\frac{1}{2}(y - F)^2 = -(y - F)$, negated: $y - F$. For log loss, $\ell = -yF + \log(1 + e^F)$ (substitute $p = \sigma(F)$), so $\partial\ell/\partial F = -y + \sigma(F) = p - y$; negated, $y - p$.

2. For a leaf with value $c$ added to the current $F_i$: minimize $\sum_i \ell(y_i, F_i + c)$. One Newton step from $c = 0$: $c = -\frac{\sum g_i}{\sum h_i}$ with $g_i = p_i - y_i$ and $h_i = p_i(1 - p_i)$ (the second
   derivative of the log loss in $F$). So $c = \frac{\sum(y_i - p_i)}{\sum p_i(1 - p_i)}$.

3. The objective for leaf $j$ is $\sum_{I_j}[g_iw_j + \frac{1}{2}h_iw_j^2] + \frac{\lambda}{2}w_j^2 = G_jw_j + \frac{1}{2}(H_j + \lambda)w_j^2$. Setting the derivative to zero: $w_j^* = -G_j/(H_j + \lambda)$; plugging back in, the
   value is $-\frac{1}{2}G_j^2/(H_j + \lambda)$. A split replaces one leaf's value with two, and adds a leaf (cost $\gamma$): gain = (reduction with two leaves) − (reduction with one) − $\gamma$, which is the formula.

4. The exponential loss of a point with margin $yF = -5$ is $e^5 \approx 148$, and its gradient grows just as fast, so a single mislabeled point that the model (correctly) disagrees with dominates the
   next rounds. Log loss grows only linearly for large negative margins ($\log(1 + e^5) \approx 5$) and its gradient is bounded by 1, so mislabeled points can't take over.

5. Smaller steps follow the functional gradient path more closely and let many trees each contribute a little, which averages out the noise in any single tree's fit (a regularization
   effect), and early stopping can pick the stopping point more finely. The cost is more rounds: training and prediction time grow roughly as $1/\nu$.
