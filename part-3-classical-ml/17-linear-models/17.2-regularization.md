# 17.2 Regularization: ridge, lasso, elastic net

*About 9 hours. Prerequisites: 17.1, 02.3 and 02.4 (least squares, SVD), 03.2 (convexity), 04.4 (MAP), 16.2. Lab: [`lab_17_2_regularization.py`](labs/lab_17_2_regularization.py).*

17.1 left you with two problems it couldn't solve. Correlated features make individual coefficients unstable, and with more features
than rows ($p > n$) least squares doesn't even have a unique answer. Both are variance problems (16.2), and the standard cure is the same:
stop asking the model for the best fit, and ask for the best fit *that isn't too extravagant*. You pay a little bias and buy a lot of variance
reduction.

This is the most reused idea in the course. Weight decay in neural networks (26.3) is ridge. The L1 penalty is how compressed sensing and
sparse models work. The $\lambda$ you tune here is the same knob, under different names, in every model after this one. Learn it properly once.

## Ridge regression

Add the squared L2 norm of the coefficients to the loss:

$$\hat\beta_{\text{ridge}} = \arg\min_\beta \; \|y - X\beta\|_2^2 + \lambda\|\beta\|_2^2 \quad\Rightarrow\quad \hat\beta_{\text{ridge}} = (X^\top X + \lambda I)^{-1}X^\top y$$

(Set the gradient $-2X^\top(y - X\beta) + 2\lambda\beta$ to zero.) Three things to notice:

- $X^\top X + \lambda I$ is invertible for any $\lambda > 0$, even when $X^\top X$ is singular. Ridge always has a unique solution, including $p > n$.
- **The SVD view** (02.4) is the one that explains everything. With $X = U\Sigma V^\top$, the OLS fit uses each singular direction at full weight;
  ridge multiplies the component along direction $j$ by $\frac{\sigma_j^2}{\sigma_j^2 + \lambda}$. Directions with large singular values (well determined by the data)
  are barely touched; directions with tiny singular values (the near-collinear ones that made 17.1's coefficients wobble) are shrunk almost to nothing.
  Ridge doesn't shrink everything equally; it shrinks what the data can't support.
- **Effective degrees of freedom**: $\text{df}(\lambda) = \sum_j \frac{\sigma_j^2}{\sigma_j^2 + \lambda}$, which goes from $p$ at $\lambda = 0$ to 0 as $\lambda \to \infty$.
  It's the honest measure of model complexity, better than counting parameters (16.3's footnote about capacity, made concrete).

Ridge coefficients shrink toward zero but are never exactly zero (for finite $\lambda$ and non-degenerate data). Every feature stays in the model.

## Lasso

Replace the squared L2 penalty with the L1 norm:

$$\hat\beta_{\text{lasso}} = \arg\min_\beta \; \frac{1}{2n}\|y - X\beta\|_2^2 + \lambda\|\beta\|_1$$

(The $\frac{1}{2n}$ is scikit-learn's convention; papers vary, so a $\lambda$ from one source doesn't transfer to another without checking.) No closed form
this time, because $|\beta_j|$ isn't differentiable at zero. But that kink is exactly the point: **the lasso sets coefficients to exactly zero**. It does
feature selection and shrinkage at once.

Why exactly zero? Three views, all worth having:

1. **Geometry.** The penalized problem is equivalent to minimizing the squared error subject to $\|\beta\|_1 \le t$ (Lagrange duality, 03.2). The L1 ball is a
   diamond with corners on the axes. The elliptical contours of the squared error usually touch it first at a corner, where some coordinates are zero.
   The L2 ball is round, has no corners, and the touching point has zero coordinates only by coincidence.
2. **Optimality conditions.** At the lasso solution, for every feature $j$ (standardized, 17.1), $\frac{1}{n}|x_j^\top r| \le \lambda$ if $\hat\beta_j = 0$ and
   $\frac{1}{n}x_j^\top r = \lambda\,\text{sign}(\hat\beta_j)$ otherwise, where $r$ is the residual. A feature enters the model only when its correlation with the residual reaches $\lambda$.
   Below that, zero is not a boundary case but a whole interval of optimality.
3. **One coordinate at a time.** For one standardized feature with the others fixed, the lasso update is **soft-thresholding**:
   $$\hat\beta_j \leftarrow S_\lambda(z) = \text{sign}(z)\max(|z| - \lambda, 0), \qquad z = \tfrac{1}{n}x_j^\top(y - X_{-j}\beta_{-j})$$
   Anything with $|z| \le \lambda$ goes to exactly zero; everything else is pulled toward zero by $\lambda$. The ridge equivalent is $z/(1 + \lambda)$: shrunk, never zero.

View 3 is also the algorithm. **Coordinate descent** cycles through the features applying that update until nothing changes. It's what scikit-learn and
glmnet run, it's fast, and you'll implement it in the lab in about fifteen lines, then check it against scikit-learn to several decimals.

### The regularization path

Solve for a decreasing sequence of $\lambda$ values, warm-starting each from the previous solution (cheap, because solutions change smoothly). At
$\lambda_{\max} = \frac{1}{n}\max_j|x_j^\top y|$ every coefficient is zero; as $\lambda$ falls, features enter one by one. Plotting coefficients against $\lambda$ gives
you the **lasso path**, which is more informative than any single fit: it shows the order in which features earn their place.

### Where the lasso misbehaves

- **Correlated features.** From a group of highly correlated features the lasso tends to pick one, somewhat arbitrarily, and zero the rest. Resample
  the data and it may pick a different one. If you're going to present "the features the lasso selected" as a finding, bootstrap it first
  (stability selection) and prepare to be disappointed.
- **Bias on the survivors.** The same $\lambda$ that zeroes weak features shrinks the strong ones too. A common fix is the **relaxed lasso**: use the lasso to
  select, then refit (unpenalized or lightly penalized) on the selected features.
- **Inference after selection is broken.** Running OLS on lasso-selected features and reading the p-values from 17.1 gives intervals that are too
  narrow, because the same data chose the features and tested them (16.3's best-of-many problem). Post-selection inference exists; the naive
  version isn't it.
- **At most $n$ features** can be nonzero when $p > n$.

## Elastic net

Combine the two:

$$\frac{1}{2n}\|y - X\beta\|_2^2 + \lambda\Big(\alpha\|\beta\|_1 + \frac{1-\alpha}{2}\|\beta\|_2^2\Big)$$

(scikit-learn calls the mixing parameter `l1_ratio` and the overall strength `alpha`. Yes, the names are swapped relative to glmnet. No, I don't
know why either.) The L1 part gives sparsity; the L2 part gives the **grouping effect**: correlated features get similar coefficients and enter or leave
together, instead of the lasso's arbitrary pick. It's what I reach for when features come in correlated groups (sensor arrays, one-hot encoded
hierarchies, genomics, text n-grams).

## Priors, constraints and the same idea everywhere

From 04.4: penalized least squares is MAP estimation. Gaussian noise plus a Gaussian prior $\beta_j \sim \mathcal{N}(0, \tau^2)$ gives ridge with
$\lambda = \sigma^2/\tau^2$. A Laplace prior gives the lasso. So "how strong should the penalty be?" is "how strongly do you believe coefficients are
small?", which is a statement about your features, and it's why standardization matters (next section).

A caution on the Bayesian reading: the lasso is the posterior *mode* under a Laplace prior. The posterior *mean* under that prior is never sparse.
If what you want is a sparse Bayesian model, the lasso is a shortcut, not the real thing (horseshoe priors are the real thing; out of scope here).

## Practicalities

- **Standardize** the features before penalizing. The penalty treats all coefficients alike, so a feature measured in millimeters (big values, small
  coefficient) is penalized far less than the same feature in kilometers. Without standardization, your choice of units selects your features. Fit the scaler
  inside the cross-validation pipeline (18.4), not on all the data.
- **Don't penalize the intercept.** Center $y$ and the features, or let the library handle it (scikit-learn does).
- **Choose $\lambda$ by cross-validation** (18.1) over a log-spaced grid. `RidgeCV` (efficient leave-one-out for ridge), `LassoCV` and `ElasticNetCV` do the
  whole path. The **one-standard-error rule**: take the largest $\lambda$ whose CV error is within one standard error of the minimum. You get a simpler model
  that's statistically indistinguishable from the best one.
- **Categorical features** one-hot encoded: with a penalty you can keep all levels (no reference level needed, the penalty resolves the redundancy),
  though then the coefficients depend on the penalty's choice of how to split the effect.
- **Naming chaos.** In scikit-learn, `Ridge(alpha=...)` and `Lasso(alpha=...)` take penalty strength, while `LogisticRegression(C=...)` takes its *inverse*.
  Bigger `alpha` = more regularization; bigger `C` = less. This has caused more bugs than I'd like to admit.

## Things that will bite you

- **Penalizing unstandardized features.**
- **Fitting the scaler on all the data** before cross-validation (leakage, 18.4).
- **Comparing $\lambda$ values across libraries** with different loss scalings, or confusing `alpha` with `C`.
- **Treating lasso-selected features as "the important ones"** without checking stability.
- **Reading p-values after selection.**
- **Forgetting the lasso shrinks the features it keeps**, then wondering why predictions are biased toward the mean.

## Exercises

1. Derive the ridge closed form, and show that in the SVD basis it multiplies the OLS component along direction $j$ by $\sigma_j^2/(\sigma_j^2 + \lambda)$.
2. Derive the soft-thresholding update for one standardized feature in the lasso (use subgradients: $\partial|b| = \text{sign}(b)$ for $b \ne 0$ and $[-1, 1]$ at 0).
3. Show that $\lambda_{\max} = \frac{1}{n}\max_j|x_j^\top y|$ is the smallest $\lambda$ for which the lasso solution is all zeros (centered data).
4. Two features are identical copies of each other. What does ridge do with them? And the lasso?
5. A colleague fits a lasso on income in millions of dollars and age in days, without standardizing, and concludes income doesn't matter. What went wrong?

1. Gradient: $-2X^\top(y - X\beta) + 2\lambda\beta = 0 \Rightarrow (X^\top X + \lambda I)\beta = X^\top y$. With $X = U\Sigma V^\top$: $X^\top X + \lambda I = V(\Sigma^2 + \lambda I)V^\top$, so

2. With the other coefficients fixed and $\frac{1}{n}x_j^\top x_j = 1$, the objective in $b$ is $\frac{1}{2}b^2 - zb + \lambda|b|$ plus a constant. Subgradient: $b - z + \lambda\,\partial|b| \ni 0$.
   If $b > 0$: $b = z - \lambda$, valid when $z > \lambda$. If $b < 0$: $b = z + \lambda$, valid when $z < -\lambda$. Otherwise $0 \in -z + \lambda[-1, 1]$, i.e. $|z| \le \lambda$, and $b = 0$.
   Together: $S_\lambda(z)$.

3. At $\beta = 0$ the residual is $y$. Zero is optimal iff for every $j$, $\frac{1}{n}|x_j^\top y| \le \lambda$ (exercise 2's condition). The smallest $\lambda$ satisfying all of them is the max.

4. Ridge splits the effect equally between them (each gets half of what one copy would get), because for a fixed sum, $b_1^2 + b_2^2$ is minimized at equality. The
   lasso is indifferent to how the sum is split ($|b_1| + |b_2|$ is constant for same-sign splits), so the solution isn't unique, and the solver typically puts it all on
   one of them. Elastic net's L2 part breaks the tie toward the equal split.

5. Write $\beta_j x_j = (\beta_j s_j)(x_j / s_j)$ with $s_j$ the feature's standard deviation. The effect per standard deviation is $\gamma_j = \beta_j s_j$, and the penalty
   $\lambda|\beta_j| = (\lambda / s_j)|\gamma_j|$. Income in millions has a tiny $s_j$ (a few hundredths), so each unit of real effect is penalized enormously and it gets
   zeroed first. Age in days has $s_j$ in the thousands and is barely penalized at all. The selection reflects the units, not the data. Standardize and refit
   before concluding anything (and even then, check whether income is correlated with something that was kept).
