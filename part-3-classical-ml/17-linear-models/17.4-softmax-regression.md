# 17.4 Multiclass, softmax and the road to neural nets

*About 8 hours. Prerequisites: 17.3, 06.1 (cross-entropy), 07.2 (stable softmax and log-sum-exp), 03.1 (chain rule). Lab: [`lab_17_4_softmax.py`](labs/lab_17_4_softmax.py).*

Logistic regression answers yes/no. Most real classification problems have more than two answers: which of ten digits, which of four customer
segments, which of forty thousand products. This lesson generalizes logistic regression to $K$ classes, and then, because the generalization is so
clean, it takes one more step and shows you that the thing you just built is the last layer of every classification neural network. When you
get to Part IV, the only new idea will be *learning the features*. Everything else, you'll have already written by hand here.

## Two ways to go multiclass

**One-vs-rest (OvR)**: train $K$ binary classifiers, "class $k$ vs everything else", and predict the class whose classifier is most confident. Simple,
parallel, works with any binary classifier. The catch: the $K$ probabilities don't sum to 1, each classifier sees an imbalanced problem, and the scores
aren't comparable across classifiers in any principled way. Fine for ranking, awkward if you need probabilities.

**Multinomial (softmax) regression**: one model that outputs a proper probability distribution over the $K$ classes. It's the default in scikit-learn's
`LogisticRegression` for multiclass problems, and it's what neural networks use. The rest of this lesson is about it.

(There's also one-vs-one, $K(K-1)/2$ pairwise classifiers with voting, which SVMs traditionally use (19.3). Mentioned so you recognize it.)

## The softmax model

Give each class its own weight vector $w_k$ (stack them as the columns of $W \in \mathbb{R}^{d \times K}$) and compute a **logit** per class, $z_k = x^\top w_k + b_k$.
Turn the logits into probabilities with the **softmax**:

$$P(y = k \mid x) = \operatorname{softmax}(z)_k = \frac{e^{z_k}}{\sum_{j=1}^K e^{z_j}}$$

Positive, sums to 1, and monotone in each logit. Three properties to internalize:

- **Shift invariance.** Adding the same constant to every logit changes nothing. That's what makes the stable implementation work (subtract the max, 07.2),
  and it means the parameters are **not identifiable**: add any vector to every $w_k$ and the predictions are identical. Fix it by pinning one class's weights
  to zero (the statistician's reference class) or by regularization (the ML default, which picks the minimum-norm representative).
- **With $K = 2$ it's logistic regression.** $\operatorname{softmax}(z)_1 = \frac{1}{1 + e^{-(z_1 - z_0)}} = \sigma(z_1 - z_0)$: only the difference of the two logits matters.
- **Log-odds between any two classes are linear**: $\log\frac{P(k \mid x)}{P(j \mid x)} = x^\top(w_k - w_j) + (b_k - b_j)$. The decision boundary between two classes is a hyperplane,
  and the regions where each class wins are convex polytopes. That's the model's power and its limit.

**Temperature.** Dividing the logits by $T$ before the softmax sharpens ($T < 1$) or flattens ($T > 1$) the distribution without changing the ranking. You'll meet it
in calibration (18.3, "temperature scaling"), knowledge distillation (49.3) and LLM sampling (37.1), always doing the same job.

## Loss and gradient

With one-hot labels $Y$ (row $i$ has a 1 in column $y_i$) and predicted probabilities $P$, the negative log-likelihood is the **categorical cross-entropy** (06.1):

$$\mathcal{L}(W, b) = -\frac{1}{n}\sum_i \log P_{i, y_i} = \frac{1}{n}\sum_i\Big(\log\sum_j e^{z_{ij}} - z_{i,y_i}\Big)$$

The second form is the one to implement: a log-sum-exp minus the correct logit, both computed stably from the logits, never from probabilities that might
have underflowed to 0. Frameworks bundle softmax and cross-entropy into one function for exactly this reason (PyTorch's `cross_entropy` takes logits, 25.1; passing
it probabilities is a classic bug that trains, just badly).

The gradient with respect to the logits is the same beautiful thing as in 17.3:

$$\frac{\partial\mathcal{L}}{\partial Z} = \frac{1}{n}(P - Y), \qquad \nabla_W\mathcal{L} = \frac{1}{n}X^\top(P - Y), \qquad \nabla_b\mathcal{L} = \frac{1}{n}\mathbf{1}^\top(P - Y)$$

"Predicted minus actual", times the inputs. The loss is convex in $(W, b)$, so gradient descent (or L-BFGS, or Newton with a $dK \times dK$ Hessian if you're patient) finds the
global optimum. The lab derives this, implements it in about ten lines of NumPy, checks the gradient numerically (03.1's finite differences, the habit that
will save you in 24.3) and matches scikit-learn.

## The limit of linear models

A linear classifier can only draw hyperplanes in the feature space you give it. The classic counterexample is XOR: points at $(0,0)$ and $(1,1)$ in one class, $(0,1)$ and
$(1,0)$ in the other. No line separates them (you checked this in 16.3 with shattering). Real data is full of XOR-like structure: "risky if young *and* a sports
car, but not if either alone", "fraud if the device is new *and* the amount is unusual".

There are two ways out, and the difference between them is the history of machine learning.

**1. Engineer the features.** Add $x_1x_2$ and XOR becomes linearly separable. Polynomial features, interactions, binning, domain ratios (16.1's fuel type ×
consumption): the model stays linear in its parameters, the features do the nonlinear work. Kernel methods (19.3) do this implicitly with infinitely many
features. For a long time, this *was* machine learning: most of the effort went into features, and the model at the end was logistic regression or an SVM.
It's still how a lot of production tabular ML works (22.1), and it's interpretable, debuggable and cheap.

**2. Learn the features.** Instead of choosing the transformation $\phi(x)$ by hand, parameterize it and learn it along with the classifier:

$$h = \text{ReLU}(xW_1 + b_1), \qquad P(y \mid x) = \operatorname{softmax}(hW_2 + b_2)$$

That's a **neural network with one hidden layer**. Look at the second line: it's exactly the softmax regression from this lesson, applied to learned features $h$
instead of raw $x$. The gradient for $W_2$ is exactly the formula above with $h$ in place of $X$. The gradient for $W_1$ comes from pushing $(P - Y)$ back through $W_2$ and
the ReLU with the chain rule, which is backpropagation (24.2). The loss is no longer convex (the ReLU and the product $W_1W_2$ see to that), so there are no global
guarantees, and yet, in practice, it works remarkably well (Module 26 explains as much of the "why" as anyone currently understands).

The lab solves XOR three ways: a linear model (fails, at 50%), a linear model with the product feature (perfect), and a two-layer network written in NumPy with
hand-derived gradients (perfect, having discovered its own features). The network is about fifteen lines. When you read 24.1 and 24.2, come back to it.

## When linear models are the right answer

Now that you know their limits, a defense, because people abandon them too quickly:

- **Tabular data with good features**: often within a point or two of gradient boosting (20.3, 20.4), and much easier to explain, monitor and debug.
- **Very high-dimensional sparse data** (text as bag of words, one-hot categorical with millions of levels, click logs): linear models with L1/L2 are fast, strong
  and scale to billions of rows. Ad-click prediction ran on regularized logistic regression for many years.
- **As a baseline** (16.1). Always. If your deep model can't beat a tuned logistic regression, you've learned something important about your problem or your
  deep model.
- **When you need calibrated probabilities, coefficients to show a regulator, or a model that fits in a SQL expression.**
- **As the last layer** of everything else.

## Things that will bite you

- **Computing cross-entropy from probabilities** instead of from logits (underflow, `log(0)`, NaN).
- **Passing probabilities to a loss that expects logits**, or applying softmax twice.
- **Interpreting per-class coefficients individually**; only differences between classes are identified.
- **OvR scores treated as probabilities.**
- **Giving up on linear models** before trying interaction and ratio features.

2. Show that softmax regression with $K = 2$ is logistic regression, and say what the logistic coefficient is in terms of $w_0$ and $w_1$.
3. Why does adding the same vector $v$ to every $w_k$ leave the predictions unchanged? How does L2 regularization pick one solution among them?
4. A model outputs logits $(2.0, 1.0, 0.1)$. Compute the softmax at temperature 1 and at temperature 0.5. What happens as $T \to 0$ and as $T \to \infty$?
5. Write down the gradient of the cross-entropy with respect to $W_1$ in the one-hidden-layer network above. (It's fine to be sloppy about the ReLU at exactly 0.)

1. For one example, $\ell = \log\sum_j e^{z_j} - z_y$. $\frac{\partial}{\partial z_k}\log\sum_j e^{z_j} = \frac{e^{z_k}}{\sum_j e^{z_j}} = P_k$, and $\frac{\partial z_y}{\partial z_k} = [k = y] = Y_k$. So $\partial\ell/\partial z_k = P_k - Y_k$; average over $n$.

2. $P(y = 1) = \frac{e^{z_1}}{e^{z_0} + e^{z_1}} = \frac{1}{1 + e^{-(z_1 - z_0)}} = \sigma\big(x^\top(w_1 - w_0) + (b_1 - b_0)\big)$. The logistic coefficient is $w_1 - w_0$: only the difference is identified.

3. $z_k + x^\top v$ for every $k$ is a common shift of all logits, and softmax is shift invariant. Among all $W + v\mathbf{1}^\top$, L2 penalizes $\sum_k\|w_k + v\|^2$, minimized at
   $v = -\frac{1}{K}\sum_k w_k$: the solution where the class weight vectors sum to zero.

4. $T = 1$: $e^{2}, e^{1}, e^{0.1} = 7.39, 2.72, 1.11$, sum 11.21 → $(0.659, 0.242, 0.099)$. $T = 0.5$: logits $(4, 2, 0.2)$ → $54.6, 7.39, 1.22$, sum 63.2 → $(0.864, 0.117, 0.019)$.
   $T \to 0$: all mass on the argmax (one-hot). $T \to \infty$: uniform $(1/3, 1/3, 1/3)$.

5. With $a = xW_1 + b_1$, $h = \text{ReLU}(a)$, $z = hW_2 + b_2$: $\delta_z = \frac{1}{n}(P - Y)$; $\delta_h = \delta_z W_2^\top$; $\delta_a = \delta_h \odot [a > 0]$; $\nabla_{W_1} = X^\top\delta_a$, $\nabla_{b_1} = \mathbf{1}^\top\delta_a$.
