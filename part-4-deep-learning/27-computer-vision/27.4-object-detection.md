# 27.4 Object detection

*About 10 hours. Prerequisites: 27.1 to 27.3, 18.2 (precision, recall, average precision), 18.4 (imbalance). Lab: [`lab_27_4_detection.py`](labs/lab_27_4_detection.py).*

Classification answers "what's in this image?". Detection answers "what's in this image, where, and how many?": a set of boxes, each with a class and a
confidence. It's the task behind self-driving perception, warehouse robots, retail shelf analytics, medical lesion finding, and every security camera
product that promises to count people. It's also harder in ways that matter for engineering: the output is a variable-size set, most of the image is
background, objects come in all sizes, and the evaluation metric (mAP) is subtle enough that people report it wrong constantly.

This lesson covers the vocabulary (boxes, IoU, NMS, mAP), the main families of detectors and why each exists, and the lab builds all the evaluation
machinery from scratch plus a small anchor-free detector that trains on a CPU.

## Boxes and IoU

A box is four numbers: corners $(x_1, y_1, x_2, y_2)$, or center and size $(c_x, c_y, w, h)$, in pixels or normalized to $[0, 1]$. Every dataset and library picks a different convention (COCO uses $(x, y, w, h)$ from the top-left corner); converting
correctly is the first place detection code goes wrong.

The **intersection over union** of two boxes is the area of their intersection divided by the area of their union: 1 for identical boxes, 0 for disjoint ones. It's how predictions are matched to ground truth ("a detection is correct if
IoU ≥ 0.5 with an unmatched ground-truth box of the same class") and a common loss ingredient (GIoU and its relatives add a term so non-overlapping boxes still get a gradient).

## Non-maximum suppression

Detectors produce many overlapping predictions for the same object (nearby anchors or neighboring grid cells all fire). **NMS** keeps the highest-scoring box, removes every other box of the same class whose IoU with it exceeds a threshold
(0.5 is common), and repeats. Simple and effective, with known failure modes: two genuinely overlapping objects (a crowd) can suppress each other, and the threshold is a tradeoff between duplicates and missed neighbors. Soft-NMS
decays scores instead of deleting boxes. DETR (below) removes the need for NMS entirely. The lab implements greedy NMS and checks it against `torchvision.ops.nms`.

## Evaluation: average precision and mAP

For one class: sort all detections across the test set by confidence; walk down the list, marking each as a **true positive** if it matches an unmatched ground-truth box with IoU above the threshold, otherwise a **false positive** (including
duplicates of an already matched object). This traces a precision-recall curve (18.2). **Average precision** (AP) is the area under it, computed with the precision envelope (the maximum precision at any higher recall) to remove wiggles.
**mAP** averages AP over classes.

Two conventions, and you must say which you report:

- **Pascal VOC**: mAP at IoU 0.5 ("mAP@0.5"). Lenient on localization.
- **COCO**: mAP averaged over IoU thresholds 0.5, 0.55, ..., 0.95 ("mAP@[.5:.95]", often just "AP"). Rewards precise boxes; numbers are much lower. COCO also reports AP for small, medium and large objects, which is usually where the story is.

Pitfalls: counting duplicates as correct, matching across classes, computing AP per image instead of over the dataset, and comparing numbers computed by different tools. The lab builds AP from scratch and verifies it on cases where the
answer is known.

## The main families

**Two-stage detectors.** **R-CNN** (2014) proposed about 2,000 candidate regions with a classic algorithm, warped each to a fixed size, and classified it with a CNN: accurate and extremely slow. **Fast R-CNN** ran the CNN once per image and pooled
features for each region from the shared feature map (**RoI pooling**, later RoIAlign). **Faster R-CNN** (2015) replaced the external proposals with a **region proposal network** that predicts "objectness" and box corrections for a set of
**anchors** (reference boxes of several sizes and aspect ratios at every feature-map location). Stage one proposes, stage two classifies and refines. Accurate, and the base of Mask R-CNN (27.5).

**One-stage detectors.** **YOLO** (2016) and **SSD** predict classes and boxes densely from the feature map in a single pass: fast enough for video. Their weakness was accuracy, which **RetinaNet** (2017) traced to **class imbalance**: tens of thousands of
anchors, a handful of objects, and the easy background examples dominate the loss. Its fix, the **focal loss** $-(1 - p_t)^\gamma\log p_t$, down-weights examples the model already gets right (18.4's imbalance problem, solved inside the loss). Later YOLO
versions accumulated many such improvements and are the practical default for real-time detection.

**Anchor-free detectors** drop the hand-designed anchors: **FCOS** predicts, at each location inside an object, the distances to the four box sides; **CenterNet** predicts a **heatmap of object centers** per class plus the box size at each center,
and decodes by finding local maxima (a 3×3 max-pooling acts as NMS). Simple, and it's what the lab builds.

**Multi-scale features.** Small and large objects need different resolutions. **Feature pyramid networks** (FPN) combine the deep, low-resolution features (semantics) with shallower, high-resolution ones (detail) through a top-down path, and predict at
several scales. Nearly every modern detector uses one.

**DETR** (2020) treats detection as **set prediction**: a transformer (Module 29) outputs a fixed number of box-and-class predictions, matched one-to-one to the ground truth by the **Hungarian algorithm** during training, so duplicates are penalized and
no NMS is needed. Slow to train at first; later variants (Deformable DETR, DINO) fixed much of that and now lead benchmarks. **Open-vocabulary** detectors (OWL-ViT, Grounding DINO) combine this with image-text models (30.2) to detect
categories named in free text, without training on them.

## Practicalities

- **Data**: box annotation is expensive and inconsistent (how tight? occluded parts?). Audit a sample; label noise caps your mAP (10.3).
- **Augmentation must transform the boxes too**: flips, crops and scaling move them; crops can cut objects in half (drop or clip them by rule).
- **Resolution and small objects**: small objects are the hardest; higher input resolution or tiling helps more than a bigger backbone.
- **Thresholds**: the confidence threshold for deployment is a precision-recall decision (18.3), set per class from costs; mAP doesn't choose it for you.
- **Start from a pretrained detector** (torchvision's Faster R-CNN, a YOLO release, a DETR variant) and fine-tune (27.3).

## Things that will bite you

- **Box format mismatches** (xyxy vs xywh, pixels vs normalized).
- **mAP computed by a different convention** than the one you compare against.
- **Duplicates counted as true positives.**
- **Augmentations that don't update the boxes.**
- **NMS threshold** tuned on the test set, or one threshold for crowded and sparse scenes.
- **Reporting mAP@0.5** when the application needs tight boxes (or COCO AP when it doesn't).

4. Why did one-stage detectors lag two-stage ones before the focal loss, and what does the focal loss change?
5. Why does DETR not need NMS?

5. Its training loss matches each ground-truth object to exactly one prediction (Hungarian matching), and every other prediction is trained to output "no object". A duplicate prediction of an already matched object is penalized, so the model learns to produce one
