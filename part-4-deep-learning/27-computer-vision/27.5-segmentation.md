# 27.5 Segmentation

*About 9 hours. Prerequisites: 27.1 (transposed convolutions, receptive fields), 27.4 (IoU, instances), 18.2 (metrics under imbalance). Lab: [`lab_27_5_segmentation.py`](labs/lab_27_5_segmentation.py).*

Detection draws boxes. Segmentation labels **pixels**: this pixel is road, that one is pedestrian, those belong to the tumor. It's what medical imaging,
autonomous driving, satellite analysis, photo editing ("remove background") and industrial inspection actually need, because boxes are a poor
description of a lung, a river or a crack.

This lesson covers the three flavors of the task, the encoder-decoder architecture (U-Net) that dominates it, the instance-level extension (Mask R-CNN),
the promptable models (SAM) that changed how segmentation is used in practice, and the metrics, where pixel accuracy is the headline number that lies.

## Three tasks

- **Semantic segmentation**: a class per pixel. Two touching cars are one blob of "car".
- **Instance segmentation**: a mask per object instance, for countable "things" (cars, people, cells).
- **Panoptic segmentation**: both at once: every pixel gets a class, and pixels of countable things also get an instance ID; amorphous "stuff" (sky, road) doesn't.

## Architectures

**Fully convolutional networks** (FCN, Long, Shelhamer and Darrell, 2015) took a classification CNN, dropped the global pooling and dense head, and made it output a coarse class map, upsampled back to the image size. The problem it
exposed is the central tension of segmentation: the deep, downsampled features know *what* is there, and the early, high-resolution features know precisely *where*. A network needs both.

**U-Net** (Ronneberger, Fischer and Brox, 2015) resolves it with an **encoder** that downsamples (a CNN backbone), a symmetric **decoder** that upsamples (transposed convolutions or resize-then-convolve, 27.1), and **skip connections** that concatenate each
encoder stage's features into the decoder stage of the same resolution. Semantics flow up the middle; detail comes across the skips. Designed for biomedical images with very few training examples, it's still the default for
segmentation, and the same shape turns up as the denoiser inside diffusion models (31.3). The lab removes the skip connections and measures what happens to the boundaries: accuracy away from edges barely changes (0.998 to 0.993), accuracy on the 6% of pixels at class boundaries drops from 0.95 to 0.80.

**Keeping resolution**: **dilated (atrous) convolutions** enlarge receptive fields without downsampling; **DeepLab**'s atrous spatial pyramid pooling runs several dilation rates in parallel to capture context at several scales.

**Mask R-CNN** (He et al., 2017) extends Faster R-CNN (27.4) with a third head that predicts a small binary mask inside each detected box, using **RoIAlign** (bilinear sampling instead of RoI pooling's rounding, which misaligned masks by
up to a pixel, a lot at mask resolution). Detection plus a per-instance mask: the standard instance segmentation approach for years.

**Transformer-based models** (MaskFormer, Mask2Former) unify the three tasks as predicting a set of masks with classes, DETR-style (27.4).

## Promptable segmentation: SAM

The **Segment Anything Model** (Kirillov et al., 2023) changed the question from "segment these classes" to "segment *whatever I point at*". A heavy image encoder (a ViT, 30.2) runs once per image; a light **prompt encoder** takes clicks, boxes or
masks; a fast **mask decoder** outputs masks for the prompted object, in milliseconds, with no class labels at all. Trained on over a billion masks (collected with the model in the loop), it segments objects from domains it never saw.
Practically, it has transformed **annotation** (click once instead of tracing a polygon), and it combines with detectors and open-vocabulary models (a box from Grounding DINO as SAM's prompt gives "segment the thing named X").
SAM 2 extends it to video.

The lab builds a toy version of the *interface*: a small U-Net whose input is the image plus a channel encoding a click, trained to output the mask of the object under the click. It separates two touching objects of the
same class, which a semantic model by definition can't: on clicks on such objects it scores an IoU of 0.70, while a *perfect* semantic map plus "take the connected region under the click" scores 0.46, because it returns both objects as one.

## Metrics and losses

- **Pixel accuracy** is dominated by the background: if 85% of the pixels are background, predicting "background" everywhere scores 85%. Don't report it alone.
- **IoU per class** (the Jaccard index of predicted and true pixel sets for that class) and its mean over classes, **mIoU**, is the standard. The **Dice coefficient** $\frac{2|A \cap B|}{|A| + |B|}$ is closely related (and the norm in medical imaging).
- Report per-class IoU: the small, rare classes are usually the failures that matter.
- **Losses**: pixel-wise cross-entropy (with class weights for imbalance), or a **soft Dice loss** that optimizes the overlap directly and is less sensitive to class imbalance; combinations of the two are common.
  Cross-entropy is a sum over pixels, so when 88% of them are background (the lab's scenes), most of the gradient goes to getting the background right. Soft Dice is averaged over classes, so a class covering 2% of the pixels counts as much as the background.
  In the lab, with the same model and the same short training budget, adding Dice to cross-entropy gave a higher IoU on every shape class, most on the rarest ones.
  On the lab's seed the gap is modest (0.95 vs 0.93 mIoU). Over three seeds, Dice won each time, by 0.02, 0.19 and 0.23, and in the bad runs plain cross-entropy never learned one or two classes at all. Pixel accuracy barely noticed any of it.
  Imbalance costs you training time before it costs you accuracy, and on a tight budget or a rare class those are the same thing.
- **Boundaries** are where errors concentrate; boundary-aware metrics (boundary F-score) matter for applications like medical margins.

## Practicalities

- **Annotation is expensive**: pixel masks take minutes to hours per image. SAM-assisted labeling, weak supervision from boxes, and pretrained encoders (27.3) all reduce it.
- **Augmentations** must be applied identically to the image and its mask (nearest-neighbor interpolation for the mask, never bilinear: it would invent intermediate class IDs).
- **Resolution**: downsample too aggressively and thin structures vanish; tile large images (satellite, pathology slides) with overlap.
- **Class imbalance**: weight the loss, oversample images containing rare classes, and evaluate per class.

## Things that will bite you

- **Pixel accuracy** as the headline metric.
- **Plain cross-entropy on heavily imbalanced masks**, and a rare class that never gets learned; check the per-class IoU.
- **Bilinear interpolation of masks.**
- **Misaligned image and mask augmentations.**
- **mIoU averaged over images** vs over the dataset (different numbers; say which).
- **Tiny structures lost** to downsampling.
- **Semantic masks used where instances are needed** (counting, tracking).

## Exercises

1. An image is 90% background, 9% road, 1% bicycle. A model predicts background everywhere except for perfectly labeling the road. Compute pixel accuracy and mIoU (three classes).
2. Why does U-Net concatenate encoder features into the decoder, rather than only upsampling the bottleneck?
3. What's the difference between the Dice coefficient and IoU? Show that Dice $= 2\,\text{IoU}/(1 + \text{IoU})$.
4. Why does Mask R-CNN use RoIAlign instead of RoI pooling?
5. How would you use SAM to build a labeled dataset of 5,000 images for a new defect type, quickly?
6. Run the lab's cross-entropy vs cross-entropy + Dice comparison with seeds 1 and 2 (change the `torch.manual_seed` before each model and the `seed` argument of `train`). What happens to the per-class IoUs, and what does it tell you about reporting a comparison from one run?

2. The bottleneck features are low-resolution (1/16 or 1/32 of the input): they encode what is present but have lost where the boundaries are. Upsampling them can't recover information that was discarded. The skip connections bring in the
   high-resolution features from the same scale, which carry precise locations, so the decoder can combine semantics with detail.

3. With $I = |A \cap B|$, $U = |A \cup B| = |A| + |B| - I$: IoU $= I/U$, Dice $= 2I/(|A| + |B|) = 2I/(U + I)$. Divide numerator and denominator by $U$: Dice $= 2\,\text{IoU}/(1 + \text{IoU})$. They rank predictions the same way; Dice is larger for the same overlap.

4. RoI pooling quantizes the region's coordinates and its bins to integer feature-map cells, so the pooled features can be misaligned with the region by up to a cell (many pixels at stride 16). For boxes that's tolerable; for pixel masks it
   shifts the mask. RoIAlign samples the feature map at exact (fractional) positions with bilinear interpolation, with no rounding.
