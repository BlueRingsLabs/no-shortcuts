# 29.3 Positions, efficiency and FlashAttention

*About 11 hours. Prerequisites: 29.1, 29.2, 02.2 (rotation matrices), 25.3 (GPU memory hierarchy). Lab: [`lab_29_3_positions_efficiency.py`](labs/lab_29_3_positions_efficiency.py).*

Two problems are left over from 29.1. Self-attention can't tell "dog bites man" from "man bites dog", because it treats its input as a
set. And its cost grows with the square of the sequence length, which was fine at 512 tokens and stopped being fine when people wanted to
paste a whole codebase into a prompt. This lesson covers how position gets back in (four ways, with very different behavior on sequences
longer than the ones seen in training), and how attention got cheap enough for long contexts: mostly by not changing the math at all and
being clever about memory, which is FlashAttention's whole story.

## Why positions are needed

29.1 proved it: permute the input tokens, and self-attention's outputs are permuted the same way, nothing else changes. A language model with no positional information sees a bag of words (with one leak: the causal mask means position 5 attends to 5 tokens and position 500 to 500, from which a model can infer *something* about position; "NoPE" models exploit this, Kazemnejad et al., 2023). The lab's no-position model gets 39% on a task that needs to know which token came just before; with positions, 92% to 97%.

## Absolute positions: sinusoidal and learned

The original transformer **adds** a fixed vector to each token embedding:

$$PE(p, 2i) = \sin(p \cdot \omega_i), \qquad PE(p, 2i+1) = \cos(p \cdot \omega_i), \qquad \omega_i = 10000^{-2i/d}.$$

Each pair of dimensions is a clock hand turning at its own speed, from once every $2\pi$ positions down to once every $2\pi \times 10000$. The property Vaswani et al. wanted: for a fixed offset $k$, $PE(p + k)$ is a **rotation** of $PE(p)$ by a matrix that depends only on $k$, so relative offsets are linear functions of the encoding and the model can learn to use them. The lab verifies it to $10^{-15}$.

**Learned absolute** positions (BERT, GPT-2) are just an embedding table indexed by position. Simple and effective within the trained length, and **undefined beyond it**: there is no row 2049 in a 2048-row table. The lab's learned-position model can't even run on longer inputs.

## Relative positions: RoPE and ALiBi

What usually matters is how far apart two tokens are, not where they are. Relative schemes inject position into the **attention scores** instead of the embeddings.

**RoPE**, rotary position embedding (Su et al., 2021), rotates each pair of dimensions of the query at position $m$ by angle $m\theta_i$, and the key at position $n$ by $n\theta_i$, before the dot product. Since rotations compose, $(R_m q)^\top (R_n k) = q^\top R_{n-m} k$: the score depends only on the offset $n - m$ (and on the content), and not on where the pair sits in the sequence.
Nothing is added to the embeddings; values aren't rotated. The lab checks that the same $q$ and $k$ at positions (10, 3), (110, 103) and (1010, 1003) give identical scores, while (3, 10) differs: RoPE tells before from after. It's what Llama, Mistral, Qwen and most open models use.

**ALiBi** (Press, Smith and Lewis, 2022) is even simpler: no rotation, no embedding, just subtract $m_h \cdot (i - j)$ from the score of query $i$ attending to key $j$, with a fixed slope $m_h$ per head (a geometric sequence, so some heads look far and some near). A soft recency bias.

**Length extrapolation**, trained at 64 tokens and tested at 64, 128 and 256 on the lab's copying task:

| Positions | 64 | 128 | 256 |
|---|---|---|---|
| learned absolute | 0.925 | can't run | can't run |
| sinusoidal | 0.892 | 0.879 | 0.782 |
| RoPE | 0.973 | 0.971 | 0.901 |
| ALiBi | 0.943 | 0.970 | 0.981 |
| none | 0.394 | 0.351 | 0.317 |

(ALiBi's accuracy rises because longer sequences contain more repeats to copy from, and its bias knows only distance.) The pattern matches the literature: ALiBi extrapolates best, RoPE extrapolates somewhat and then degrades as it meets rotation angles it never trained on, and absolute schemes don't extrapolate. In real LLMs, RoPE's degradation beyond the training length is severe, so long-context models **extend** it rather than rely on extrapolation.
**Position interpolation** (Chen et al., 2023) squeezes the new, longer positions into the trained range by dividing them by the extension factor, then fine-tunes briefly; **NTK-aware scaling** and **YaRN** (Peng et al., 2023) scale the frequencies unevenly, keeping the fast-rotating dimensions (local order) intact and stretching the slow ones. That's how a model pretrained at 4k or 8k tokens gets a 128k context.

Extrapolating is one thing; *using* a long context is another. Models retrieve information from the beginning and end of a long prompt much better than from the middle ("lost in the middle", Liu et al., 2023), and a context window of 128k tokens is a limit, not a promise. Test it on your task (39.1).

## The cost of attention

For a sequence of length $n$ and head size $d$, attention computes an $n \times n$ score matrix per head: $O(n^2 d)$ time and, naively, $O(n^2)$ memory. At $n = 128{,}000$, one head's scores in fp16 are 32 GB. Two different problems hide in there:

- **Memory traffic, not arithmetic**, is what makes naive attention slow on a GPU. The $n \times n$ matrix is written to the GPU's main memory (HBM), read back for the softmax, written again, read again for the multiply by $V$. GPUs do arithmetic far faster than they move data (25.3); attention is **memory-bound**.
- **The KV cache** at generation time: every layer stores the keys and values of every previous token. It grows linearly with context and batch, and for long contexts it's bigger than the model (37.2).

## FlashAttention

FlashAttention (Dao et al., 2022) computes **exact** attention, the same numbers up to floating-point rounding, without ever writing the $n \times n$ matrix to HBM. It tiles $Q$, $K$ and $V$ into blocks that fit in the GPU's fast on-chip memory (SRAM), and for each block of queries walks over the blocks of keys and values, accumulating the output.

The obstacle is the softmax: it needs the maximum and the sum over the **entire** row before any output can be computed. The fix is the **online softmax** (Milakov and Gimelshein, 2018): keep a running maximum $m$, a running denominator $\ell$ and a running output $o$; when a new block of scores arrives with a larger maximum, rescale the old $\ell$ and $o$ by $e^{m_{\text{old}} - m_{\text{new}}}$ and add the new block's contributions. At the end, divide $o$ by $\ell$.
The lab implements it in twenty lines and matches the full computation to $4 \times 10^{-16}$, with blocks of $64 \times 64$ instead of a $1024 \times 1024$ matrix. For the backward pass, FlashAttention stores only the softmax statistics and **recomputes** the scores block by block (the activation checkpointing of 24.2 and 33.1, applied inside one operation): more arithmetic, far less memory traffic, and faster overall.

Results: attention memory linear in $n$ instead of quadratic, and a 2 to 4 times speedup; FlashAttention-2 and -3 improved the parallelism and the use of newer GPUs. It's what made 32k-token and longer training practical, and it's the default: PyTorch's `F.scaled_dot_product_attention` dispatches to it (or to a similar memory-efficient kernel) when the inputs allow. **If you write attention as `softmax(q @ k.T) @ v` in production code, you're choosing the slow, memory-hungry version.**

## Changing the math: sparse, sliding and linear attention

Before FlashAttention made exact attention cheap enough, and still for very long sequences, people changed what's computed:

- **Sparse patterns**: each token attends to a subset. **Sliding window** (local attention over the last $w$ tokens; Longformer, Mistral 7B's first version) makes cost $O(nw)$; stacking layers still lets information travel $L \times w$ positions. Longformer and BigBird add a few **global** tokens that attend everywhere.
- **Linear attention** (Katharopoulos et al., 2020): replace $\exp(q^\top k)$ with $\phi(q)^\top \phi(k)$ for a feature map $\phi$. Then $\sum_j \phi(q)^\top\phi(k_j) v_j^\top = \phi(q)^\top \left(\sum_j \phi(k_j) v_j^\top\right)$, and for a causal model the sum in parentheses is a **state** updated once per token: linear attention *is* an RNN (28.1), with a $d \times d$ matrix as its hidden state. The lab checks that the parallel and recurrent forms agree to $10^{-16}$.
  The catch is the other side of the same fact: everything the model remembers has to fit in that fixed state, while softmax attention keeps every past key and value. Linear attention was consistently worse at recall-heavy tasks.
- **State space models** (S4, Mamba) and modern linear RNNs (RWKV, RetNet, gated linear attention) are the descendants: recurrent at inference, parallel in training, with better-designed state updates. They're competitive at moderate scales and are increasingly used in **hybrids** that interleave a few full-attention layers with many cheap recurrent ones.

For most applications today the answer is: exact attention with FlashAttention, GQA (below) for the cache, and long-context techniques for the positions.

## Shrinking the KV cache: MQA and GQA

Each layer caches keys and values: $2 \times L \times h_{kv} \times d_{head} \times n$ numbers per sequence. **Multi-query attention** (Shazeer, 2019) shares a single key/value head across all query heads; **grouped-query attention** (Ainslie et al., 2023) shares one per group of query heads, a middle ground that loses little quality. For a Llama-2-70B-like shape (80 layers, 64 query heads of size 128) and a 32k-token sequence in bf16, the lab computes: 86 GB with full multi-head attention, 10.7 GB with 8 KV heads (what Llama 2 70B uses), 1.3 GB with one. The weights themselves are 140 GB. GQA is standard in current open models; 35.5 and 37.2 continue the story (and **multi-head latent attention**, which compresses the cache further).

## Things that will bite you

- **Learned positions** used beyond the trained length (an index error if you're lucky, garbage if the code clamps).
- **RoPE applied to values**, or with a different base or pairing convention than the checkpoint was trained with (interleaved pairs vs split halves: both exist, they're not interchangeable).
- **Trusting a long context window** without testing retrieval from the middle.
- **Hand-written attention in production** instead of the fused kernel.
- **Masks that force the slow path** (some custom masks disable the FlashAttention kernel; check which backend runs).
- **Forgetting the KV cache** in memory planning for long contexts.

## Exercises

1. For sinusoidal encodings with $d = 512$, what are the shortest and longest wavelengths (in positions)?
2. Show that for a single RoPE pair with frequency $\theta$, $(R_m q)^\top (R_n k)$ depends only on $n - m$. (Hint: treat each pair as a complex number.)
3. A model with learned positions was trained at length 2048. What happens at position 3000, and how would you extend it?
4. Write the online softmax update for a new block of scores $s$ given the running $m$, $\ell$, $o$.
5. Why is linear attention an RNN, and what does that imply about what it can remember?
6. Compute the KV cache in bf16 for 32 layers, 8 KV heads of size 128, 128k tokens, batch 4.

1. Frequency $\omega_i = 10000^{-2i/d}$, $i = 0, \dots, 255$. Wavelength $2\pi/\omega_i$: shortest $2\pi \approx 6.3$ positions ($i = 0$); longest $2\pi \cdot 10000^{510/512} \approx 2\pi \times 9{,}647 \approx 60{,}600$ positions.

2. Write the pair as complex numbers: $q \to q e^{im\theta}$, $k \to k e^{in\theta}$. The real dot product of two 2D vectors is $\operatorname{Re}(a \bar b)$, so the score is $\operatorname{Re}(q e^{im\theta}\, \overline{k e^{in\theta}}) = \operatorname{Re}(q \bar k\, e^{i(m - n)\theta})$, a function of $m - n$ only. (The sign convention flips $m - n$ vs $n - m$; either way, only the offset appears.)

3. There's no embedding for position 3000: in PyTorch, an index error; some code clamps or wraps positions, which produces garbage silently. Options: interpolate the learned table to a longer length (as ViTs do for higher resolution, 30.2) and fine-tune on long sequences; or switch to a relative scheme, which requires more fine-tuning. RoPE models instead get position interpolation or YaRN.

4. $m' = \max(m, \max_j s_j)$; $\ell' = \ell\, e^{m - m'} + \sum_j e^{s_j - m'}$; $o' = o\, e^{m - m'} + \sum_j e^{s_j - m'} v_j$; set $m \leftarrow m'$, and so on. At the end, output $o/\ell$.

5. With a feature map $\phi$, the causal output at step $t$ depends on the past only through $S_t = \sum_{j \le t}\phi(k_j)v_j^\top$ and $z_t = \sum_{j\le t}\phi(k_j)$, which are updated by adding one term per token: a recurrence with a fixed-size state. So its memory of the past is a fixed $d \times d_v$ matrix, however long the sequence: it must compress, and exact recall of many specific past tokens (a phone number from 10,000 tokens ago) degrades as more is written. Softmax attention stores every key and value and can retrieve any of them exactly.

6. $2 \times 32 \times 8 \times 128 \times 131{,}072 \times 4 \times 2$ bytes $= 68.7 \times 10^9$ bytes, about 69 GB (16 GiB per sequence).
