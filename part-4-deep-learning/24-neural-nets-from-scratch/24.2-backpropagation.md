# 24.2 Backpropagation, derived properly

*About 10 hours. Prerequisites: 03.1 (chain rule, Jacobians), 03.2, 24.1, 17.4 (softmax cross-entropy gradient). Lab: [`lab_24_2_backprop.py`](labs/lab_24_2_backprop.py).*

Backpropagation is the chain rule, applied to a computation graph in a specific order, with a specific trick for not wasting work. That's all it is.
It's also the algorithm that made deep learning possible, and the one people most often use without understanding, which is fine until the day a
custom layer produces NaNs, a gradient is silently wrong by a factor of the batch size, or training uses four times the memory you budgeted. On that
day you need to know exactly what `loss.backward()` computes and stores.

In this lesson you derive backprop for an MLP in matrix form, then generalize it to "every operation knows its vector-Jacobian product", which is how
every framework works. The lab builds a small layer library in NumPy, gradient-checks every piece, and matches PyTorch to machine precision.

## Computation graphs and the chain rule

Any computation of a scalar loss $L$ from parameters is a directed acyclic graph of simple operations: matrix multiplies, additions, elementwise functions, reductions. For a chain $x \to u \to v \to L$, the chain rule
(03.1) gives $\frac{\partial L}{\partial x} = \frac{\partial L}{\partial v}\frac{\partial v}{\partial u}\frac{\partial u}{\partial x}$, a product of Jacobians. The question is the **order** in which to multiply them.

- **Forward mode** multiplies from the input side: propagate $\frac{\partial u}{\partial x}$, then $\frac{\partial v}{\partial x}$, and so on. Each pass gives derivatives of everything with respect to **one input direction**. With $p$ parameters, you need $p$ passes.
- **Reverse mode** multiplies from the output side: start with $\frac{\partial L}{\partial L} = 1$, then compute $\frac{\partial L}{\partial v}$, then $\frac{\partial L}{\partial u}$, and so on backward. Each pass gives derivatives of **one output** with respect to everything.

A neural network has one scalar output (the loss) and millions of parameters. Reverse mode computes the whole gradient in **one backward pass costing a small constant times the forward pass** (roughly 2 to 3 times).
Forward mode would need a million passes. That asymmetry is why backprop exists (Rumelhart, Hinton and Williams, 1986; the reverse-mode idea goes back to Linnainmaa, 1970). The lab times both.

The price: the backward pass needs intermediate values from the forward pass (the activations), so they must be **stored**. Activation memory, not parameter memory, is usually what limits the batch size of a large network,
and **activation checkpointing** (recomputing some activations during the backward pass instead of storing them) trades compute for memory (33.1).

## Backprop for an MLP, in matrix form

Take one example (the batch version follows). Layer $\ell$: $z^{(\ell)} = W^{(\ell)}h^{(\ell-1)} + b^{(\ell)}$, $h^{(\ell)} = \phi(z^{(\ell)})$, with $h^{(0)} = x$ and a loss $L$ on the last layer's output. Define the **error signal** $\delta^{(\ell)} = \partial L / \partial z^{(\ell)}$, a vector the size of layer $\ell$.

1. **Output layer**: for softmax with cross-entropy (or sigmoid with BCE, or identity with squared error), $\delta^{(L)} = \hat y - y$ (17.3, 17.4).
2. **Backward recursion**: $z^{(\ell+1)}$ depends on $z^{(\ell)}$ through $h^{(\ell)}$, so
   $$\delta^{(\ell)} = \big(W^{(\ell+1)\top}\delta^{(\ell+1)}\big) \odot \phi'(z^{(\ell)})$$
   Pass the error back through the transposed weights, then gate it by the activation's derivative.
3. **Parameter gradients**: $\dfrac{\partial L}{\partial W^{(\ell)}} = \delta^{(\ell)}h^{(\ell-1)\top}$ (an outer product: error of the output unit times activity of the input unit), and $\dfrac{\partial L}{\partial b^{(\ell)}} = \delta^{(\ell)}$.

**Batches**: with examples as rows ($Z^{(\ell)} = H^{(\ell-1)}W^{(\ell)\top} + b^{(\ell)}$) and a loss averaged over the batch, the same equations become $\Delta^{(\ell)} = (\Delta^{(\ell+1)}W^{(\ell+1)}) \odot \phi'(Z^{(\ell)})$,
$\nabla_{W^{(\ell)}} = \Delta^{(\ell)\top}H^{(\ell-1)}$, $\nabla_{b^{(\ell)}} = \mathbf{1}^\top\Delta^{(\ell)}$ (sum over the batch), with $\Delta^{(L)} = (\hat Y - Y)/B$. Two sanity rules catch most mistakes:

- **The gradient of a parameter has the parameter's shape.** If your $\nabla W$ comes out transposed, you've swapped an order.
- **Anything broadcast in the forward pass is summed in the backward pass.** The bias is added to every row, so its gradient sums the rows. Forget the sum and you get a shape error if you're lucky and a silently
  wrong gradient if broadcasting "fixes" it for you.

## The general version: vector-Jacobian products

Frameworks don't know about "MLPs". They know operations, and each operation knows how to map the gradient with respect to its output, $\bar y = \partial L/\partial y$, to the gradients with respect to its inputs: a
**vector-Jacobian product** (VJP), $\bar x = J^\top\bar y$, computed without ever forming the Jacobian (which for a matmul on a batch would be enormous).

| Operation | Forward | Backward (VJP) |
|---|---|---|
| Matmul | $Y = XW$ | $\bar X = \bar YW^\top$, $\bar W = X^\top\bar Y$ |
| Add with broadcasting | $Y = X + b$ | $\bar X = \bar Y$, $\bar b = $ sum of $\bar Y$ over broadcast axes |
| Elementwise $\phi$ | $Y = \phi(X)$ | $\bar X = \bar Y \odot \phi'(X)$ |
| ReLU | $Y = \max(X, 0)$ | $\bar X = \bar Y \odot [X > 0]$ |
| Sum over an axis | $y = \sum_i x_i$ | $\bar x_i = \bar y$ (broadcast back) |
| Mean over $n$ | $y = \frac{1}{n}\sum_i x_i$ | $\bar x_i = \bar y / n$ |
| Softmax + CE (fused) | $L = -\frac{1}{B}\sum\log\text{softmax}(Z)_{y}$ | $\bar Z = (\text{softmax}(Z) - Y)/B$ |
| A variable used twice | $y = f(x), z = g(x)$ | $\bar x = \bar x_{\text{via } f} + \bar x_{\text{via } g}$ (gradients **accumulate**) |

Backprop is then: run the forward pass recording each operation and its inputs (the **tape**), then walk the tape in reverse, calling each operation's VJP and **adding** the result into the gradients of its inputs.
The last row of the table is why the gradients are *added*: a value used in several places receives gradient from each. It's also why PyTorch accumulates into `.grad` and why you call `zero_grad()` (25.1).
24.3 builds exactly this engine.

## Checking gradients

A hand-written or custom gradient is wrong until proven otherwise. The check (03.1): perturb each parameter by $\pm\varepsilon$ and compare the **central difference** $\frac{L(\theta + \varepsilon) - L(\theta - \varepsilon)}{2\varepsilon}$ with the analytic gradient,
using the **relative error** $\frac{|g_a - g_n|}{\max(|g_a|, |g_n|, \text{tiny})}$. In float64 with $\varepsilon \approx 10^{-5}$ to $10^{-6}$, a correct gradient gives relative errors around $10^{-7}$ or smaller; $10^{-3}$ means a bug. Check a few random
coordinates of each parameter, on a tiny network and batch, with ReLU kinks away from zero (a kink between $\theta \pm \varepsilon$ breaks the check without a bug). And do it in float64: in float32 the check itself is too noisy (07.2).

## Beyond the gradient

- **Forward mode** (Jacobian-vector products) is the right tool when there are few inputs and many outputs, and it's how you get **Hessian-vector products** cheaply (forward-over-reverse), used in some second-order
  methods and in analyzing the loss curvature (26.2).
- **Gradients of gradients** (double backprop) appear in gradient penalties (WGAN-GP, 31.2) and meta-learning.
- **Non-differentiable points** (ReLU at 0, max, sorting) get a subgradient by convention. **Discrete operations** (sampling a token, argmax) have no useful gradient; you need estimators (straight-through,
  REINFORCE, 46.5) or reparameterization (31.1).

## Things that will bite you

- **A gradient off by the batch size** (sum vs mean in the loss, and the backward pass not matching).
- **Forgetting to sum** over broadcast axes.
- **Transposes** in the wrong place in a hand-written backward.
- **Gradient checks in float32**, or across a ReLU kink.
- **Gradients accumulating** across steps because nobody zeroed them.
- **Activation memory** blowing up with batch size and depth, while everyone stares at the parameter count.

   gradient, silently.
