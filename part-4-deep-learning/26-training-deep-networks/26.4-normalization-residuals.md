# 26.4 Normalization and residual connections

*About 8 hours. Prerequisites: 24.1 (vanishing gradients), 24.2, 26.2 (initialization, signal propagation), 25.2 (train/eval modes). Lab: [`lab_26_4_norm_residual.py`](labs/lab_26_4_norm_residual.py).*

With good initialization (26.2), a 10-layer network trains. A 50-layer one, built the same way, often trains *worse* than a 20-layer one: not worse on
test data (that would be overfitting), worse on its own **training** data. He et al. (2016) called this the **degradation problem**, and it shouldn't
happen, since the deeper network could copy the shallower one and set its extra layers to the identity. The optimizer just can't find that solution.

Two inventions fixed it, and together they're why networks with hundreds of layers train routinely today: **residual connections**, which make the identity
easy, and **normalization layers**, which keep every layer's inputs in a well-behaved range no matter what the layers before them did. Every modern
architecture (ResNets, transformers, diffusion U-Nets, every LLM) is built from blocks that combine the two. This lesson explains both and builds the
normalization layers from scratch.

## Residual connections

Instead of $h_{\ell+1} = F(h_\ell)$, compute

$$h_{\ell+1} = h_\ell + F(h_\ell)$$

where $F$ is a small block (two layers, say). The block learns a **residual**: a correction to its input rather than a whole new representation.

Why it helps, three ways:

- **The identity is free.** With $F$'s weights near zero, the block is the identity, so adding blocks can't make the starting point worse. Initializing the last layer of each block to zero (26.2) makes the whole network start as the identity.
- **Gradients have a highway.** $\frac{\partial h_{\ell+1}}{\partial h_\ell} = I + \frac{\partial F}{\partial h_\ell}$. The product of these Jacobians across layers always contains the identity term, so the gradient reaching early layers can't vanish just because the $F$ Jacobians are small (24.1's
  product of small factors). The lab measures per-layer gradient norms in a 50-layer plain network and its residual twin.
- **An ensemble of shallow paths.** Unrolled, a residual network is a sum over $2^L$ paths of different lengths; most of the gradient flows through the shorter ones, and deleting a single block barely hurts a trained ResNet, unlike a plain network
  (Veit, Wilber and Belongie, 2016).

When the block changes the dimension (a convolution with stride 2, 27.2), the skip path gets a projection (a 1×1 convolution or a linear layer).

## Batch normalization

For each feature (each channel, in a CNN), normalize over the **batch**:

$$\hat x = \frac{x - \mu_B}{\sqrt{\sigma_B^2 + \epsilon}}, \qquad y = \gamma\hat x + \beta$$

with $\mu_B, \sigma_B^2$ the mean and variance of that feature over the current mini-batch, and learnable $\gamma, \beta$ (so the layer can undo the normalization if that's what's best). During training it also keeps **running averages** of
$\mu$ and $\sigma^2$ (buffers, 25.2); in **evaluation** it uses those instead of batch statistics, so a single example's prediction doesn't depend on its batch-mates.

BatchNorm (Ioffe and Szegedy, 2015) made much higher learning rates usable and much deeper CNNs trainable. The original explanation, reducing "internal covariate shift", turned out not to be the reason; the better-supported one
is that it makes the loss **smoother** (gradients change less abruptly), which permits larger steps (Santurkar et al., 2018). It also makes each layer invariant to the scale of the weights feeding it, which is 26.3's weight-decay
subtlety.

Its costs are all consequences of "normalize over the batch":

- **Small batches** give noisy statistics; below 8 or so per device, BatchNorm hurts. The lab trains with batch size 2.
- **Train/eval mismatch**: running statistics that don't match the evaluation data (a model trained on one domain, evaluated on another; running averages not converged; `eval()` forgotten, 25.2) give silently wrong predictions.
- **Examples in a batch affect each other** in training mode. That breaks the assumption that examples are independent, which matters for some methods (contrastive learning can "cheat" through it, 30.1) and for per-example
  gradients (25.1). The lab shows one example's output changing when the rest of its batch changes.
- **Multi-GPU training** needs synchronized statistics across devices (SyncBatchNorm), or each GPU normalizes over its own small slice.
- **Sequence models** with variable lengths and recurrent steps don't fit the "statistics over the batch" idea well.

## LayerNorm, RMSNorm, GroupNorm

- **LayerNorm** (Ba, Kiros and Hinton, 2016): normalize over the **features of each example**, not over the batch. Same formula, different axis. No dependence on the batch, identical behavior in training and evaluation, works with any
  batch size and with sequences. The standard in transformers (29.2).
- **RMSNorm** (Zhang and Sennrich, 2019): skip the mean subtraction and divide by the root mean square: $y = \gamma\,x/\sqrt{\text{mean}(x^2) + \epsilon}$. Slightly cheaper, and in practice as good; used by most recent LLMs (35.5).
- **GroupNorm** (Wu and He, 2018): normalize over groups of channels within each example. The CNN answer to small batches (detection and segmentation models, 27.4, 27.5).

## Where the normalization goes: pre-norm vs post-norm

In a residual block, normalization can go **after** the addition (**post-norm**: $h + F(h)$, then normalize; the original transformer) or **inside the branch, before $F$** (**pre-norm**: $h + F(\text{Norm}(h))$). Pre-norm keeps a clean identity path from input to
output (the residual stream is never normalized), so gradients flow well even in very deep stacks and training is stable without careful warmup; post-norm can reach slightly better results when it trains, but needs warmup and
careful tuning at depth. Almost all modern LLMs use pre-norm (with a final normalization at the end), 29.2 and 35.5.

## Things that will bite you

- **BatchNorm with tiny batches.**
- **Forgetting `eval()`**: the running statistics get updated by test data, and predictions depend on the batch.
- **Fine-tuning a BatchNorm network** on a small dataset without freezing its statistics (they drift to the small dataset's noise; 27.3).
- **Mismatched domains** between training statistics and deployment data.
- **Bias before BatchNorm**: redundant (the mean subtraction cancels it). Use `bias=False` in the layer before.
- **Deep plain networks** built by habit, without residual connections.
- **Normalizing the residual stream itself** (post-norm) at great depth without warmup.

## Exercises

1. Show that $\frac{\partial h_{L}}{\partial h_0}$ for a residual network is a product of $(I + J_\ell)$ terms, and expand it for $L = 2$. Why can't it vanish the way $\prod J_\ell$ can?
2. Write the forward pass of LayerNorm for an input of shape (batch, features), and say which axis BatchNorm would use instead.
3. A BatchNorm network gets 94% validation accuracy when evaluated with batch size 256 and 71% with batch size 1. What's the bug?
4. Why is a bias in a linear layer followed by BatchNorm redundant?
5. Why does pre-norm make very deep transformers easier to train than post-norm?

<details>
<summary>Answers</summary>

1. $h_{\ell+1} = h_\ell + F_\ell(h_\ell)$ gives $\partial h_{\ell+1}/\partial h_\ell = I + J_\ell$, and the chain rule multiplies them: $\partial h_L/\partial h_0 = \prod_\ell(I + J_\ell)$. For $L = 2$: $(I + J_1)(I + J_0) = I + J_0 + J_1 + J_1J_0$. The identity term (and all the short paths) survive even if every $J$ is tiny, while
   $\prod J_\ell$ alone shrinks geometrically.

2. `mu = x.mean(dim=1, keepdim=True); var = x.var(dim=1, unbiased=False, keepdim=True); y = gamma * (x - mu) / sqrt(var + eps) + beta`, with `gamma`, `beta` of shape (features,). BatchNorm uses `dim=0` (over the batch, per feature).

3. The model is being evaluated in training mode (`eval()` not called), so BatchNorm normalizes with the statistics of the evaluation batch; with batch size 1 each feature's variance is 0 and the normalized values are meaningless. Call
   `model.eval()` so the running statistics are used; then accuracy doesn't depend on the evaluation batch size.

4. BatchNorm subtracts the per-feature batch mean, which removes any constant added to that feature, including the bias; then $\beta$ adds a learned offset back. The layer's bias has no effect on the output and just wastes a parameter and
   an update.

5. With pre-norm, the residual stream $h$ passes from input to output through additions only, so the gradient has a direct identity path to every layer, and each block's contribution is normalized before it's used, which bounds its
   scale. With post-norm, every block's output is renormalized, so the identity path passes through $L$ normalization layers whose Jacobians compound, which destabilizes early training at depth unless the learning rate is warmed up
   carefully.
